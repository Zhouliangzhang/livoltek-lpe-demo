# iEMS现场工作台产品需求文件

英文产品名 iEMS Site Engineering Workbench
文件编号 IEMS-PRD-001　版本 V1.1　日期 2026年11月9日

状态：V1.1 迭代评审稿。统一产品命名，并纳入2026年11月9日确认的分步拓扑与公共总览方案。保留V1.0及原始依据，不改变历史记录标识。适用读者：产品、研发、测试、iEMS控制软件、设备驱动、厂家技术服务与EPC工程团队。本文定义目标产品和验收范围；正式产品发布须完成相应评审，不将演示功能视为生产能力。

## 1 产品定义

iEMS现场工作台是iEMS面向EPC工程师和厂家技术服务人员的Web工程作业界面。它帮助iEMS认识完整相关系统，形成有来源的配置，执行受控调试，向EPC交付技术资料、向厂家RSP建立服务档案，并在售后阶段依据基线和现场证据定位故障、处置与复测。

同一个项目、同一套对象标识、同一条证据链贯穿M1至M4。M1和M2是同一位现场工程师的连续工作，直接“继续调试”，无需内部签收、再次建项目或重录设备。M3才发生面向EPC接收方和厂家平台的外部交付。M4可以由RSP派单，也可以本地受理。

本产品由四个模块组成：M1系统建模与设置、M2调试与SAT、M3项目交接、M4现场服务。浏览器负责交互与呈现；配置写入和测试由可信iEMS执行服务完成。真实设备保护及受控退出不依赖浏览器或互联网持续在线。

### 1.1 用户问题与产品目标

当前需要解决的问题包括：设备资料分散、第三方及电气结构缺失、型号与实物身份混淆、配置重复录入、通信在线被误当作控制有效、模拟结果被误当作现场通过，以及交付后服务无法追溯当时配置。

产品目标是一次建立可复用的系统上下文，自动带出适用参数和验证步骤，以证据说明完成了什么、还有哪些限制。每个异常都应找到具体对象、依据、处理方和下一动作。

| 目标编号 | 可验收目标 | 衡量方式 |
| --- | --- | --- |
| G01 | M1至M4自动继承设备和配置 | 标准项目跨模块必需字段重复录入次数为0；新授权和现场观测不计入重复 |
| G02 | 每台设备结果可追溯 | 范围内每台必需设备均有独立身份、结果或明确未完成原因 |
| G03 | 环境不混用 | 自动测试中跨环境执行、计数、签署和回执误用为0 |
| G04 | 异常可处理 | 所有阻断项具备原因、责任接口、影响动作和有效定位目标 |
| G05 | 服务有完整证据链 | 服务报告能反查工单、交接基线、故障原始证据、措施和复测 |
| G06 | 不错误宣告完成 | 指令确认不等于生效、模拟不等于现场、入库不等于技术确认，均有反例验收 |

效率指标如录入耗时、诊断耗时和首次解决率在试点采集后建立基准；本稿不虚构节省比例。

### 1.2 范围和职责

系统建模覆盖LIVOLTEK设备、关联第三方设备及PCC、母线、汇流柜、馈线、断路器等非SN结构。完整建模用于配置、影响分析和故障根因排查，不自动扩大厂家对项目设计、施工或运营的责任。

| 主体 | 主要职责 | 权限与责任限制 |
| --- | --- | --- |
| EPC工程师及项目授权方 | 工程设计与现场真实性、作业条件、采用值、变更授权、交付整合 | 厂家适用性确认不能由EPC填姓名替代 |
| LIVOLTEK技术服务与产品团队 | 所供产品、iEMS、驱动及技术资料的适用性；产品问题分析与质量闭环 | 不承诺整站持续运营效果；也不能以系统问题为由排除所供产品缺陷 |
| 第三方设备厂家 | 对应设备点表、接线、固件适用性及控制边界 | EPC协调取得；不得默认LIVOLTEK为第三方适用性背书 |
| 业主或授权运维方 | 运行条件、数据共享及服务访问授权 | 数据共享、诊断、写入、远程控制分别授权 |
| SAT见证与签署方 | 项目约定范围内的见证和验收决定 | 平台角色不自动授予合同签署权 |
| RSP平台 | 服务建档、工单和受控协同、版本及回执 | 平台入库不等于SAT、技术正确性或保修批准 |

排除范围：EPC施工计划、设备就位安排、资源和工期管理、专业电气设计计算、法定检验、全项目合同验收、日常运营调度、收益优化及整站运营保证。厂家技术协同可以安排支持时间窗、对象和资料，不扩展为施工计划。

### 1.3 本期产品边界

首发生产范围拟聚焦并网光伏加储能、单PCC、单iEMS、零馈计量及相关配电和通信对象。数据结构保留多控制域扩展，但多PCC、多iEMS、离网、黑启动、并离网切换、发电机、无功和电能质量测试需独立能力包及验收，不由本期测试自动覆盖。

CI20为验收样例：10台125kW光伏，10台125kW／261kWh储能，1台iEMS和PCC零馈计量。标称合计PV 1.25MW、BESS 1.25MW／2.61MWh。演示页曾用2.612MWh命名，正式数据必须以适用型号主数据核定；不得静默修改批准容量。单iEMS控制20台主设备是本例方案，辅助节点是否计数和轮询负荷仍须厂家能力证明。

## 2 统一流程与工作环境

主流程：M1建模及设置 → M2调试及SAT → M3共同基线 → EPC技术交付与RSP服务建档 → RSP工单或本地报障 → M4诊断、处置、复测与报告 → 必要时生成服务后新基线并同步。

| 环境 | 允许成果 | 不允许产生的结论 |
| --- | --- | --- |
| OFFLINE 离线编制 | 工程草稿、资料整理、可追溯文件草案 | 在线身份确认、实际读回、现场通过、平台接收 |
| SIMULATION 模拟 | 全流程演练、合成故障、模拟回执及模拟关单 | 现场SAT、真实维修、真实平台建档或批准 |
| REAL 现场 | 可信身份、授权和实际证据下的工程动作 | 用模拟量或最后有效值填补未知现场数据 |

硬件在环作为专项验证模式，需单独标记每个输入和动作的真实／模拟来源，不可默认归为现场SAT。暂不作为首发普通环境选项。

环境标签始终可见，所有基线、任务、报告、附件及导出包携带环境。模拟工程复制到现场只能形成新草稿，清除模拟身份、批准、执行及通过标记。未知值为空并附原因，不能以0或“已在线”替代。

统一继续规则：每步允许保存草稿；点击继续时校验本步及下一动作必需字段。无依赖的编辑可以继续，有依赖的执行保持阻断。厂家待确认项须说明缺少哪份型号／固件依据，不是通用免责标签。取消独立L6运行条件检查入口，规则嵌入填写、继续、冻结和执行。

## 3 信息架构与页面规则

顶部保留项目、环境、iEMS身份、基线版本及一致状态。M1按12步、M2按14步作业顺序展示当前任务；M3显示两个交付路径；M4显示故障受理、引导诊断、处置与复测、服务报告四个阶段。

主要作业区采用纵向页面。设备详情默认收起，选中设备才显示；扫码、第三方录入和结构添加嵌入对应作业。型号说明按型号、固件适用范围和驱动版本合并，逐台SN、地址及结果独立记录，异常优先展示。

M1系统拓扑随工程数据逐步形成。步骤01至02确认项目、能源组成、边界和控制范围；步骤03以结构清单与归属树为主；步骤04将实际设备关联至结构和回路；步骤05展示端口级电气单线拓扑；步骤06展示通信路径与逻辑控制图；步骤07至09补充通信、计量与运行策略，步骤10冻结依据。不能让步骤03的归属关系被误读为实际接线。

M1公共区域提供“系统拓扑总览”入口，默认收起，任何步骤均可打开。查看依据可选择当前草案或当前环境的历史冻结基线，查看图层可选择电气、通信、控制及结构归属。当前草案注明工程版本和未保存修改，随已进入模型的数据更新；尚在局部编辑表单中的输入，在保存前不进入拓扑。冻结视图展示原封存范围、来源修订、环境、时间及内容标识，不混入当前草案的数据。部分范围快照不得冒充全项目模型。

电气主图按主配电、光伏、储能和负载分组。各汇流支路可继续分组以保持可读性，上级母线的跨区引用不是新增资产。所有电气连接必须来自所选版本中有效的两端端口关系；结构父子关系、命名和布局规则均不得生成接线。无端口、未连接及失效引用标为待补或待核实；备用端口不自动判为缺项。PCC表示并网边界和计量位置，不能凭布局推定电气串联关系。

通信与逻辑控制使用独立图层，同一图中同一iEMS只显示一次；逻辑控制不代表独立线缆或已获得写权限。M1图只允许缩放查看，不能拖拽、重接、删改或改变结构；滚轮滚动页面，缩放使用按钮。参数或接线变化应在对应步骤修改，布局不写回工程模型。M2／M4可点选关系查看详情及高亮相关端点，不改变模型。

“定位处理”必须携带模块、步骤、对象和参数，打开后高亮目标并提供返回入口。无权限或对象已被替换时展示原快照及当前对应关系，不能跳到一个无关首页。

## 4 M1系统建模与设置

进入条件：用户已确定项目与环境，可先编制离线草稿。完成标志：本次范围的配置基线、部署／读回事实及未完成项可以被M2引用。M1不输出系统可正常运行或SAT通过结论。

### 4.1 十二步功能要求

| 需求编号 | 步骤及操作 | 自动处理与输出 | 继续或执行约束 |
| --- | --- | --- | --- |
| M1-01 | 确认项目与iEMS | 识别站点、身份、版本和角色，建立工作上下文 | 写入前可信身份绑定；IP和SN文本不足以认证 |
| M1-02 | 定义系统边界 | 录入国家、时区、EPC、LV/MV、能源、方式、PCC和控制域；生成规划框架 | 不支持的方式不生成可执行配置 |
| M1-03 | 建立电气结构 | 建立PCC、变压器区、母线、汇流、馈线和开关的归属与图纸引用 | 缺规格为待EPC核定，不自动作保护或配线设计 |
| M1-04 | 录入设备身份 | LIVOLTEK扫码取可信厂家主数据；第三方优先模板；关联结构和回路 | 实际SN、固件、位置逐台；无适用依据保持待确认 |
| M1-05 | 建立电气连接 | 两端先选对象后选兼容端口；唯一兼容可用端口自动选中 | 两端端口与回路明确；域或额定信息未知不得称兼容 |
| M1-06 | 建立通信与控制关系 | 记录设备、网关、总线、iEMS及控制域；区分通信、计量信号和逻辑控制 | 通信可达不等于获得控制权；未知发现对象不自动纳管 |
| M1-07 | 配置通信 | 仅按已有路径显示串口／网络参数，同总线公共参数统一设置 | 地址在寻址域内唯一；模板与型号、固件、驱动匹配 |
| M1-08 | 配置计量 | PCC到电表、字段和换算链；CT/PT、方向、单位、质量和刷新规则 | 避免重复倍率；无效和零值不同；方向现场验证留M2 |
| M1-09 | 配置运行策略 | 按方式和能力带出零馈、PV限制、BESS充放电及降级恢复设置 | 站级限制不能覆盖BMS；缺少依据不生成现场控制放行 |
| M1-10 | 冻结配置基线 | 选择范围，计算依赖，展示变更差异，冻结不可变快照 | 保存草案、冻结、批准分开；范围不能删除必需依赖 |
| M1-11 | 下发与读回 | iEMS逐台执行，记录前值、确认、独立读回、差异及退出状态 | 后端及iEMS复核权限、批准、版本和实际条件 |
| M1-12 | 继续调试 | 自动引用当前适用基线、任务、读回证据、缺项进入M2 | 不设内部交接审批；M2重新核验实际条件和控制授权 |

### 4.2 身份和参数规则

扫码内容只作为识别线索，通过可信服务或已核验离线包取得厂家字段。型号、规格、端口和厂家版本不可由普通用户直接改成批准主数据。出厂固件与现场当前固件分开，扫码取得的SN仍需与本次实物关联。

第三方模板必须有提供方、版本、型号／固件适用范围和依据。无模板允许自定义草案和上传点表；不能因同为Modbus就推定兼容。资产更换保留旧新实例映射，不复制SN或已通过状态。

每个参数分别记录计划值、批准值、现场实际值及来源、时间、单位、质量、风险和依据。未知不是已完成。采用实际值替换计划值是明确变更，须重新形成版本。

储能可用功率由项目限值、实时有效设备反馈、SOC、BMS允许和其他适用限制共同决定；缺少必需输入的设备不能计入已确认可调容量。M1只定义策略和限制，不直接发出试验充放电命令。

## 5 M2调试与SAT

M2由iEMS内嵌测试执行器按依赖顺序执行。工程师确认范围、现场条件及动作授权，页面自动显示结果；不得用人工打钩覆盖自动失败。只读自动检查与有功率影响的动作分别授权。

### 5.1 十四步工作要求

| 需求编号 | 步骤 | 必需验证内容 | 完成成果 |
| --- | --- | --- | --- |
| M2-01 | 会话与冻结依据 | 沿用M1，核对控制器、范围、规程、外部作业记录和依赖 | 会话引用与未完成项，无重复录入 |
| M2-02 | iEMS自检及控制权 | 引擎、存储、时钟、日志、接口、身份、策略冲突和控制租约 | 自检证据；无写权仍可允许的只读诊断 |
| M2-03 | 零馈表通信与计量 | 身份、路径、参数、质量、方向、倍率、独立参照和连续有效性 | PCC可信范围及限制，不凭同源数据自证 |
| M2-04 | 光伏通信与身份 | 逐台型号、SN、固件、逻辑位置、功率、状态、限值、权限及告警 | 全组逐台能力和映射；Ping不构成通过 |
| M2-05 | 储能通信与能力 | BESS／PCS／BMS身份关系、SOC、适用SOH、温度、允许方向、功率边界和联锁 | 每台实时能力快照，禁止以额定值代替 |
| M2-06 | 配置读回核对 | 实际iEMS、电表、PV、BESS参数与M1批准基线比较 | 参数级差异；已在M1部署的内容不重复下发 |
| M2-07 | 光伏限功率 | 逐台核验权限及工况，指令、确认、实际功率响应和恢复 | 每台控制证据；无光或能力不足为条件不足 |
| M2-08 | 储能充放电 | 每个方向动作前核对SOC、BMS、实时功率／能量边界、确认、响应及恢复 | 充电和放电独立结果，未测方向不算通过 |
| M2-09 | 稳态零馈联动 | PCC反馈、PV限功率和BESS协调、目标带和退出 | 整站曲线、参与范围及恢复记录 |
| M2-10 | 动态响应 | 负载突变、PV波动、储能充电受限；测响应时间及恢复 | 场景级曲线、超调／越界、限制和设备异常 |
| M2-11 | 降级与恢复 | 电表失联／数据异常、PV拒令、BESS拒充、复合故障及恢复复发 | 降级动作、未知区间、两段稳定观察和解除依据 |
| M2-12 | 正常配置与连续观察 | 撤销临时设置、核对配置和所有者，按批准工况连续观察 | 退出已确认和稳定证据；异常重新计时 |
| M2-13 | 结果汇总与SAT | 条款到范围、步骤及证据的覆盖；见证、偏差、签署 | 报告版本；自动测试结论与SAT签署分开 |
| M2-14 | 封存进入M3 | 冻结报告、配置、原始证据、异常和限制 | 一份共同交接依据，原记录保持不变 |

M2-06以读回为主。确需修正时回到M1形成变更任务；经批准的通信引导配置或临时测试覆盖值也必须留痕，不在M2另建一套长期配置主数据。

### 5.2 自动判定和停止

每项测试包含进入条件、动作影响、授权、执行、反馈核对、判定、受控退出和证据保存。执行状态、结果、依据适用性和环境分别记录。必要输入未知或判据缺失时显示证据不足或待确认，不能因没有报警自动判通过。

同型号同适用范围合并主题，显示通过x／y、失败、未测及条件不足数量。逐台控制默认串行，共享PCC控制动作互斥；只读按驱动能力限流。单台异常可继续独立读取其他设备，全系统控制前必需设备必须满足条件；缩小范围必须重新计算依赖和授权。

浏览器停止按钮表示“请求受控退出”，不等于物理急停。控制权丢失、引擎重启、关键证据无法持久化或必要反馈失效时停止新测试动作，执行预先批准退出策略；未知退出状态不得显示已恢复。

### 5.3 计量失效与恢复要求

零馈判定按批准项目条件明确采用三相合计或逐相规则；若要求逐相限制，不得以三相合计购电掩盖某相馈网。光伏和储能测试均须验证退出状态。需要设备重启或物理操作的配置进入人工停点，不允许后台自动重启。

失去PCC反馈时，实际并网点功率标为未知；估算轨道不得用于声明零馈有效。根据批准策略限制PV、调整允许范围内BESS功率；若光伏拒令且储能不能吸收，应明确“零馈无法保证”，有有效实测越限时另显示“已检测馈网越限”。不自行创造断路器跳闸策略。

电表先恢复而PV仍拒令、PV先恢复而电表仍失联，均不解除告警。全部必要条件恢复后，先连续满足恢复资格窗Tq，再按批准斜率受限恢复，连续满足稳定窗Ts后才能解除运行告警。任一阶段缺测、陈旧、拒令、越界或控制权丢失，退回降级并清零两窗。Tq、Ts和其他阈值必须来自适用依据；模拟可以使用明确标记的演练值。

### 5.4 SAT范围

报告至少包括项目环境、身份版本、条款覆盖、逐台结果、未测试方向、原始曲线与日志、恢复记录、未完成项、厂家确认项及签署范围。模拟报告始终为演练汇总；现场报告只有授权方依据适用规程签署后才具有相应SAT结论。SAT不自动替代法定检验或项目合同验收。

### 7.2 RSP工单和协同

工单必须具备来源平台、租户、站点、外部工单号、版本、派单范围、对象、现象、时间、优先级及权限引用。工作台核对本地项目、环境和可用基线。身份不符进入待核对，不能猜测绑定。重复派单不得重复建服务单；转派保留历史，不能直接使原执行任务失去记录。

RSP无法连接时，本地可以受理并开展获准诊断，稍后同步。紧急报障不以厂家建档完整为前提；缺失资料明确标为诊断限制。协同计划仅包括厂家支持安排，不管理EPC施工进度。

### 7.3 处置和关闭

可分类为所供产品缺陷、系统配置、安装、第三方设备、外部运行条件、多因素或未确认。产品侧问题包含硬件、软件、驱动和适用资料缺陷；不能自动推定某一方保修责任。

待办按EPC补充、厂家确认、第三方提供、复测执行分类，稳定ID随报告更新。提交资料、资料核验、技术确认和复测通过各自留痕。必需待办未完成、退出未知、相关复测失效或现场证据不足时不允许现场修复关单。

恢复可以早于根因完全确认，但只能显示“功能恢复，根因调查中”。若根因调查是必需事项，服务单仍保持打开。非必需后续改进可在有权确认后转入关联质量事项，不能通过改责任人消除必需项。模拟关闭不等于现场修复，也不关闭真实RSP工单。
