## 1. 产品定位与设计结论

iEMS 工程工作台是 iEMS 的工程配置与技术服务界面。EPC 工程师通过浏览器，帮助 iEMS 建立对现场系统的正确认识，配置设备接入、计量和运行约束，再把确定的依据交给 iEMS 内嵌测试程序执行调试。

四个模块分别为 M1 系统建模与设置、M2 调试与 SAT、M3 项目交接、M4 现场服务。M1 的交付物是“明确范围、具有来源、可以部署并核对的工程配置基线”，不是施工计划，也不是系统运行合格证。

本文件独立定义目标流程，不沿用既有页面、版本结构或迁移方案。下文所有“应”“必须”均为拟实现的产品要求，不表示当前软件或具体 iEMS 型号已经具备相应能力。

**设计采用按作业顺序推进的主流程，辅以对象定位修改。** 相比纯设备树，顺序流程更能暴露依赖；相比全自动发现，工程师确认更能区分“网络看见了设备”与“设备属于本控制域”。自动发现只是录入助手，不能代替现场系统建模。

### 1.1 M1 负责什么

- 描述本次 iEMS 监视、控制和诊断所需的完整相关系统，包括 LIVOLTEK、第三方设备及非 SN 电气结构。
- 将型号主数据、现场资产、端口、回路、通信路径、计量映射、控制策略关联起来。
- 按型号、固件和接线方式生成适用参数；记录计划值、批准值与现场实际值。
- 校验依赖和冲突，保存基线，控制配置部署，核对读回，向 M2 传递已知条件与限制。

### 1.2 责任边界

EPC 负责专业电气设计、设备选型与容量校核、施工及现场真实性、作业授权和适用的工程批准。厂家负责其设备主数据、驱动及固件适用性、技术约束、配置接口和支持依据。第三方设备的技术依据由该设备厂家提供，EPC 负责协调取得；不能默认由 LIVOLTEK 证明第三方设备合规。

iEMS 负责按已批准的范围执行配置任务、记录读回和版本、报告异常。厂家技术确认不替代 EPC 工程批准；工程批准不替代设备厂家适用性确认。工作台不安排设备就位、施工进度、上电顺序、法定检验或合同验收。

## 3. 工作顺序总览

主线：**进入工作台 → 定义系统 → 建立电气结构 → 录入设备 → 电气连接 → 通信与控制关系 → 通信设置 → 计量设置 → 运行策略 → 保存部署基线 → 下发与读回 → 进入 M2。**

| 顺序 | 工程师完成的工作 | 形成的结果 |
| --- | --- | --- |
| 01 | 选择项目、环境与目标 iEMS | 工作上下文和访问身份 |
| 02 | 定义运行方式、PCC 与控制边界 | L1 项目及初始系统框架 |
| 03 | 录入主配电、汇流与回路结构 | L2 非 SN 结构对象 |
| 04 | 扫码或手录设备，确认实际身份 | L3 型号与现场资产 |
| 05 | 建立端口级电气连接 | L4 电气回路 |
| 06 | 建立通信路径与控制归属 | L4 通信、逻辑控制关系 |
| 07 | 按连接方式配置接入参数 | L5 总线、网络、驱动设置 |
| 08 | 设置 PCC 计量映射、方向与倍率 | L5 可追溯的计量定义 |
| 09 | 设置运行目标、设备约束与降级恢复策略 | L5 运行配置及适用限制 |
| 10 | 确认本次范围、依据与配置差异 | 不可变的部署基线 |
| 11 | 由 iEMS 部署配置并读取实际结果 | 配置任务及逐项一致状态 |
| 12 | 移交基线与限制，建立 M2 入口 | 只读诊断或控制调试的明确范围 |

步骤是工作顺序，L1-L5 是数据组织方式，不要求用户理解数据库层级。不设置独立的 L6“运行条件检查”页面。规则在填写、继续、保存基线和部署时执行，其结果直接指向原字段。

### 3.1 继续规则

每步可以保存草稿。点击“保存并继续”时，只检查本步以及下一动作必需的信息；缺失则显示“缺什么、谁补、影响什么、去哪里处理”。不能用空字符串、0 或“未知”冒充已填。

无依赖的后续工作可继续录入，但受影响步骤保持待补充，不显示已完成。设备尚未到场时可以建计划对象；需要实际身份、通信或控制的动作必须等待实物核验。用户可以浏览后续步骤，不能借此绕过必要条件。

“厂家待确认”是一种有原因、责任人和影响范围的状态，不是万能豁免。有关参数不进入可执行配置。能够独立成立的只读诊断可先开展；需要这些依据的写入和控制动作保持锁定。

## 4. 步骤01：进入项目并确认工作环境

**目标。** 防止把一个项目的设置写入另一台控制器，或把模拟结果当作现场事实。

**工程师操作。** 登录工作台，打开或新建项目，选择“离线编制”“模拟 iEMS”或“现场 iEMS”；现场连接时核对站点及控制器身份，确认本次角色和访问范围。已有项目打开当前已保存配置，禁止自动覆盖现场内容。

**iEMS / 工作台自动处理。** 读取控制器身份、软件/驱动版本和可用接口；核对项目绑定。现场身份必须有可信的控制器认证依据，SN 和 IP 仅为其中的属性。控制器容量和驱动能力从适用能力清单读取；拿不到能力清单时标为待厂家确认。离线模式不伪造连接或实时能力。

**必填与阻断。** 项目标识、环境和操作人是起始必填。现场写入前必须完成身份绑定及写权限核验；身份不符只允许查看并定位处理。首次项目尚未登记 iEMS 资产时，暂存候选身份，步骤04完成唯一绑定。控制测试租约在 M2 建立，登录或配置权限不自动授予控制测试权限。

**界面与输出。** 顶部只保留项目、环境、iEMS 身份、配置版本与一致状态。环境标签始终可见。离线和模拟的记录分别存储；切换现场必须重新绑定，不能把模拟 SN 或验证标记带过去。

## 5. 步骤02：定义项目运行方式与系统边界

**目标。** 先告诉 iEMS“这是怎样的系统、控制到哪里”，再决定需要哪些设备和设置。

**工程师操作。** 录入国家/地区、站点时区、EPC、LV/MV、结构分类、能源组成及运行方式；按项目依据选择并网、离网或切换能力。定义 PCC、控制域、主要能源/负载组成及本次管理范围；指定并网、计量和设计文件的来源及版本。

**自动处理。** 依据选择生成初始框架：电网/PCC、主配电、光伏、储能、相关负载及 iEMS。模板节点显示“规划对象”，尚未录入的端口和连接显示“待定义”，不伪装为已核实接线。根据运行方式启用后续配置主题；不支持的运行方式明确说明，不生成可下发参数。

**必填与阻断。** 环境、能源组成、运行方式和控制边界必须明确。存在多个 PCC 时逐个定义对应的计量及控制域；不能把多 PCC 合并为一个模糊总量。地区选择只用于筛选适用配置包，不自动等同于电网规范已获批准。

**界面与输出。** 一页完成项目定义，其下显示自动生成的系统框架。输出 L1 初始模型及待补对象，不在此显示 L2-L6 的统计长条。变更运行方式后列出受影响的设置和测试，保留原配置版本。

## 6. 步骤03：建立电气结构与回路归属

**目标。** 让设备归属和功率边界有真实的电气结构支撑。

**工程师操作。** 依据 EPC 图纸录入 PCC、变压器区、MV/LV 母线、光伏汇流、储能汇流、馈线、断路器及相关回路；填写编号、所属结构、设计电压/相制、用途和图纸依据。添加电气结构的入口就在本步骤。

**自动处理。** 按主配电、光伏汇流、储能汇流生成结构分组；验证编号唯一、归属无循环、引用存在、电压层级有定义。按选定结构类型提出端口需求；允许没有 SN 的结构对象。监测状态、开关分合状态的实际值只来自有来源的现场记录或遥测。

**必填与阻断。** 本次范围相关结构必须有编号、类型、归属和依据状态。设备可以暂存于待归属列表，但不能参与依赖回路归属的控制配置。缺少汇流柜或开关时可生成待核定占位，不能自动选定额定电流、保护整定或电缆截面并视为批准。

**界面与输出。** 以可展开的结构清单为主，展示 EPC 待补项。保存后更新自动拓扑。输出 L2 结构树及回路引用，为步骤04-05提供选择项。

## 7. 步骤04：录入设备并建立型号与资产身份

**目标。** 区分“产品型号是什么”和“现场是哪一台”，减少重复手录。

**LIVOLTEK 扫码。** 扫描二维码后解析产品标识，通过可信厂家数据服务或已核验的离线数据包取得型号、规格、厂家主数据版本、端口定义和适用资料；二维码包含有效 SN 时自动录入 SN。出厂固件与当前运行固件分开记录，不能把二维码中的出厂信息直接当成当前读回。工程师只补安装位置、回路归属等现场信息；厂家字段只读，发现差错提交纠正请求。

**第三方手录。** 优先选用有版本、适用型号和固件范围的模板，再手录 SN、实际固件、位置和连接信息。无模板时允许建立自定义设备并附说明书/点表，状态为待确认。型号相近或同为 Modbus 不代表驱动兼容；未经验证不能加入可控制设备范围。

**自动处理。** 检查 SN 重复、资产唯一性、型号/固件/驱动匹配；发现的在线设备先列为候选，由工程师认领。核对 BESS 与 PCS、BMS 的父子关系；一体机内部不对外独立寻址的子设备不强制单独 SN，但必须有可追踪的身份关系。更换设备保留替换记录，并使受影响的配置读回和测试失效。

**批量规则。** 同型号、同适用固件/驱动组展示公共资料一次，展开逐台核对。复制型号配置不复制 SN、IP、站号或现场验证结果。固件适用范围不同必须拆组。设备数量仅用于规划，控制器允许的总节点数、设备类型及总线负载仍须分别核验。

**必填与界面。** 计划设备可暂缺 SN；进入现场部署前，本次涉及的实际设备须具有适用的唯一身份。二维码失效、数据包过期或型号无法匹配时保留原始扫码记录，提示厂家确认，不自动套用近似型号。默认仅展示设备列表；点击设备才展开详情，不预占整页。输出 L3 型号、资产与适用能力清单。

## 8. 步骤05：建立端口级电气连接

**目标。** 让每台设备通过确定的端口关联到真实回路，形成可用于后续诊断的电气路径。

**工程师操作。** 起点先选设备或结构对象，再选其端口；终点同样先选对象，再选端口。填写回路编号，引用 EPC 接线图；必要时记录相序、极性、PE/接地关系等适用信息，不由本系统代替 EPC 计算保护或配线规格。

**自动处理。** 从型号主数据列出端口；只有一个兼容且可用的端口时自动选中，并显示自动选择结果。端口定义缺失时创建待确认端口，不默认 AC/DC 域或额定值。验证域、电压等级、相制、端口容量约束及重复连接，区分设备单端口与支持多分支的母线节点。

**必填与阻断。** 每条已确认连接必须有两端对象和端口 ID；文字描述“接到光伏柜”不能成为完整连接。缺少端口额定信息时不能宣称电气兼容。对合法环网、联络回路等结构按声明的模板处理，不用简单“禁止环路”替代电气逻辑。

**界面与输出。** 在表单中编辑连接，保存即更新只读拓扑。图上只允许缩放查看，不允许拖拽布线、重接、删除或改变结构。输出电气连接集与相关缺项；软件图形表达不等同于竣工图或接线验收。

## 9. 步骤06：建立通信路径与控制关系

**目标。** 分清设备“怎样连上”和“由谁控制”。

**工程师操作。** 继续按“两端对象 → 两端端口”建立以太网、RS485、CAN、DI/DO 及逻辑控制关系；记录交换机、网关和总线。零馈表指定关联 PCC；光伏和储能指定控制域及所属 iEMS。RS485 记录总线成员和适用的实际接线次序，不能用逻辑星形关系冒充物理接线。

**自动处理。** 区分物理链路、协议路径、数据映射与指令所有者。例如一台设备的以太网口、IP、TCP 服务端口和网关 Unit ID 是不同属性。检查路径连续性、协议转换及必需网关；记录 CAN 的用途是系统接入还是厂家内部 PCS/BMS 通信，不能默认暴露内部控制接口。

**控制归属。** 一个控制域只设一个有效的指令仲裁者，登记上层 EMS、本地策略、定时任务及远程系统关系。通信可达不代表可写；iEMS 逻辑控制关系也不代表当前已取得设备控制权。多控制器方案只有在项目确有需要且有适用依据时启用。

**界面与输出。** 通信拓扑自动分为计量反馈、iEMS 控制关系、光伏通信和储能通信；同一 iEMS 为同一对象，跨组出现的引用必须标识。接线修改全部在本步骤表单完成。输出 L4 通信路径、总线及控制域关系，为步骤07生成参数。

## 10. 步骤07：配置通信接入与驱动参数

**目标。** 只显示连接实际需要的参数，同一总线的公共设置只填一次。

| 已选连接 | 显示内容 | 设置归属 |
| --- | --- | --- |
| Modbus RTU / RS485 | 总线串口、波特率、校验、数据位、停止位；逐台站号；适用轮询/超时设置 | 公共参数归总线，站号归设备 |
| Modbus TCP / 以太网 | IP/主机名、子网及必要路由、服务端口；驱动要求时填写 Unit ID | 网络归接口，协议地址归端点 |
| 网关转接 | 上游网络路径、下游总线及从站地址映射 | 归网关通道，防止跨通道误寻址 |
| CAN / 厂家协议 | 经型号确认的速率、节点标识、协议版本及接入权限 | 归适用总线，不套用 RS485 参数 |
| DI/DO 等接口 | 通道、信号含义、有效电平及适用失效状态 | 归端口及信号映射 |

**工程师操作。** 确认自动带出的通信设置，只补本项目的地址和路径差异。LIVOLTEK 参数来自匹配型号/固件资料；第三方来自批准模板。缺少依据的字段显示“待厂家确认：缺少……”，不填常见默认值冒充正确值。

**自动处理。** 检查同一寻址域内地址冲突、网络可达性条件、总线设置一致性和驱动适用性。地址分配只能生成候选方案，保存前显示逐台变更；不自动写入现场设备。批量继承公共设置时显示全部受影响成员及已有例外。

**引导通信例外。** 如果读回必须先更改基础通信配置，允许在步骤11按独立的已批准小范围任务执行。必须保留修改前值和重新连接方法；与运行策略无关的通信写入仍须身份、权限及影响核验。不能因“连接不上”而全网扫描写地址或重置设备。

**输出。** 接入配置、驱动引用和可读/可写能力状态。此步完成仅表示通信配置已定义；通信质量由 M2 自动验证。

## 11. 步骤08：定义 PCC 计量与数据语义

**目标。** 让 iEMS 明确“哪块表代表哪个 PCC，数据是什么意思”。

**工程师操作。** 选择零馈表及对应 PCC，确认采样位置、三相/单相、CT/PT 依据、仪表型号与点表；选择总有功功率及必要相量、告警和质量字段的映射。原始数据格式、单位、缩放及符号由适用驱动带出。

**统一约定。** 工作台内部采用 P_pcc > 0 为从电网购电、P_pcc < 0 为向电网送电；储能 P_bess > 0 为放电、P_bess < 0 为充电。这是本系统的数据约定，不强制设备厂家采用相同符号。驱动必须记录原始符号到内部符号的转换。现场实际方向验证放在 M2。

**倍率规则。** 同时保留 CT/PT 的铭牌值、仪表自身倍率设置以及驱动缩放定义。必须明确读数是一次侧值还是二次侧值；若仪表已换算一次侧，iEMS 不再次套用该倍率。每个映射保存输入单位、转换公式、输出单位及出处。缺少点表不能仅凭读值“看起来合理”确认倍率。

**数据质量设置。** 记录采样时间来源、刷新预期、过期判定、有效标志及异常检测依据。数值为 0 与没有有效数据是不同状态；无法读取的值为未知，不自动补零。超时、变化率或合理范围缺少厂家依据时标为待确认。

**界面与放行。** 用“PCC → 电表 → 通信路径 → 功率字段 → 换算”摘要展示完整链路；展开后看参数和出处。映射结构、单位和倍率未确定时阻断依赖其结果的零馈控制配置发布，允许保留草案或批准范围内的原始只读诊断。输出计量语义与 M2 待验证项。

## 12. 步骤09：配置系统运行策略与设备约束

**目标。** 从项目运行目标生成最少且适用的设置，清楚区分站级规则与设备限制。

**工程师操作。** 先选目标，再设置约束：例如并网零馈、自发自用、需量控制、分时充放电；仅显示当前型号和运行方式支持的组合。每个目标必须有执行者、适用控制域、启用条件及批准依据。

| 设置主题 | 必须明确的内容 | 依据与处理边界 |
| --- | --- | --- |
| 并网点与零馈 | PCC、允许送电上限/目标、进网余量、控制方向、控制周期及响应判据 | 上限来自项目批准条件；算法参数来自适用厂家依据 |
| 光伏限功率 | 控制方式、额定基准、绝对值/百分比换算、分配规则、爬坡、确认及恢复方式 | 逐型号/固件匹配，不能用额定功率代替当前可用功率 |
| 储能运行 | 允许充/放方向、SOC 边界、站级功率限制、预约容量、计划时段与时区 | 站级约束不能覆盖 BMS、本地保护和设备实时限制 |
| 多目标协调 | 零馈、需量、计划及其他指令冲突时的优先级与禁用条件 | 同一控制域只能有确定的仲裁规则 |
| 降级和恢复 | 电表无效、光伏拒令、储能不可用等情况下的动作与退出条件 | 具体动作、定值、稳定时间须有适用依据 |

**储能能力。** 分别定义充电、放电边界的计算输入：项目批准限值、设备有效反馈、BMS 允许、SOC 与其他约束。采用约束中更严格的边界；任何必需输入未知时，不能把铭牌额定功率计入“已确认可调容量”。动态能力由 iEMS 在运行和 M2 动作前实时复核，M1 只定义计算规则和配置限制。

**失去计量反馈。** 零馈表失联或数据无效时，将 PCC 实测值标为未知，估算值与实测值分开。根据已批准方案选择限制光伏、约束储能等动作；不能因为估算功率平衡就显示“零馈有效”。若光伏拒令且储能不可用，应明确“无法保证送电限制”，提示指定责任人并支持厂家协同；不得自行断开开关或绕过保护。

**恢复设置。** 计量、设备响应及相关条件均恢复后，进入持续稳定观察；任一必要条件再次失效，重新计时并保留告警。必须记录恢复门槛与定值出处；没有依据时不能给出自动解除告警的执行配置。

**必填与输出。** 公共设置按站级或设备组显示，型号差异才展开逐台。每个拟启用策略必须完成依赖、优先级和失效处理定义。无依据的主题保持草案并生成具体厂家确认项。输出运行配置、能力依赖和后续测试范围，不在 M1 发出充放电或限功率测试指令。

## 13. 步骤10：形成有明确范围的配置基线

**目标。** 把“已填写”转成“此次准备执行的确定内容”，避免草稿随保存直接生效。

**工程师操作。** 选择本次配置范围与目标 iEMS，查看增删改差异、涉及设备/回路、写入影响及依据，确认授权记录。可形成只读接入范围、部分设备配置范围或完整控制配置范围；范围不是通过取消必需设备来掩盖缺项。

**自动处理。** 按范围计算依赖闭包：包括必需 PCC、电表、网关、总线、设备、驱动、公共策略和约束。校验不只检查被勾选设备。不能移除零馈表后仍称“完整零馈系统配置”。已存在运行配置时，新范围不得悄悄删除范围外设备或策略。

**冻结内容。** 固定模型及配置版本、目标身份、型号/SN/固件、端口连接、通信和计量映射、控制策略、主数据/驱动/规则包版本、依据引用、批准记录、影响范围及内容哈希。哈希用于内容一致性识别，不等同于审批签名或身份认证。

**批准语义。** 厂家确认型号/固件和参数适用性；项目授权角色确认现场采用值及变更。二者独立留痕。未经授权的用户输入“已批准”或填写一个文件号，不能把草案变成批准值。依据记录至少要有签发方、版本、适用范围、有效状态、附件或受控引用及核验人。

**放行与界面。** 页面展示本次差异及仅影响本次动作的阻断项，并提供定位按钮。必需项缺失、依据失效、身份冲突或控制策略无确定优先级时禁止相关部署。可保存“有待办的工程草案”，但不能把它标为可执行基线。此步是部署确认，不增加独立运行合格检查模块。

## 14. 步骤11：由 iEMS 下发配置并核对读回

**目标。** 确定哪一台设备、哪些参数确实按本次基线生效。

**工程师操作。** 审阅目标、差异和执行影响后发起配置任务。iEMS 执行任务，浏览器只显示过程；关闭页面不改变任务身份，重新连接后查询原任务，不重复提交写入。

**iEMS 执行顺序。**

1. 重新核验身份、权限、基线哈希、目标实际版本及写入时的现场条件，防止预览后配置已被他人修改。
2. 读取并保存适用的修改前快照，生成有唯一请求标识的执行计划；按批准依赖排序，不给出跨型号通用写入顺序。
3. 支持暂存的设备先暂存再激活；不支持的设备按批准的逐项过程执行，并逐项记录确认。不能假定多设备具有原子提交能力。
4. 写入之后读取实际生效参数，规范化单位、枚举及批准的精度范围，再与批准基线比较。指令确认、控制器配置文件和下级设备实际值分别记录。
5. 汇总完全一致、部分一致、读回不支持、读回失败、值不一致、实际状态未知等结果。依据不足时保持待确认。

**实际生效与策略激活。** 写入通信、计量或策略参数可能改变运行，不能统称“无风险配置”。会改变出力、控制权或立即激活策略的操作，必须有批准的现场条件和执行程序；设备支持时保持策略未激活。不能隔离该影响时，将相应激活动作留给 M2 的受控测试阶段，M1 明确标为未激活。

**失败与恢复。** 任务中断、部分成功或回执丢失时，不显示“全部失败且已恢复”。记录已知状态，先查询当前任务和实际值，再按批准程序重试或回退。回退也可能改变运行，须验证适用性并再次读回；不支持回退时停止后续关联动作，定位具体设备和补救方法。

**界面与输出。** 以“设备/参数、批准值、实际读回、时间、状态、处理”展示差异。同型号批量操作但逐台结果独立。输出配置任务 ID、前后快照、逐项结果、失败原因和日志。显示“本次范围读回一致”，不显示“系统正常”或“SAT 通过”。

## 15. 步骤12：移交配置依据并进入 M2

**目标。** M2 直接继承 M1 数据，工程师无需再次录入设备和参数。

**工程师操作。** 选择进入只读诊断或具备条件的控制调试范围，核对受影响设备和回路。工作台展示当前基线、部署/读回状态、未激活策略、未完成项及待厂家确认项；点击问题返回原对象和字段。

**自动处理。** 生成 M1 → M2 的配置引用包，包含基线 ID/哈希、目标身份、资产/端口/连接、参数和来源、适用驱动、部署任务及读回证据、范围和依赖、待办及责任方。M2 建立调试会话时重新核验依据、授权和当前实际状态，并冻结本次会话引用；不能复用过期的“曾经一致”状态。

**放行。** 只读诊断只检查该范围必要的身份、路径、驱动和批准条件。控制测试还须有相应有效配置、权限、动作条件、厂家依据和批准规程，由 M2 按顺序再次核验。M1 缺项不必阻断一切诊断，但必须阻断依赖这些缺项的控制测试。

**变更影响。** M2 开始后修改 M1 产生新版本，旧会话保留原依据；受影响步骤及其依赖标为需重新验证。系统必须说明“哪项配置变化使哪个测试结果不再适用”。不覆盖旧 SAT 报告或 M3 交接包。

## 16. 页面与交互约定

页面自上而下为：紧凑的项目上下文、当前作业步骤、该步骤的对象清单/表单、自动生成拓扑、保存并继续。采用单列主要作业区，不使用常驻左中右三栏。步骤导航表达作业先后，不以一组 L 标签代替工作任务。

扫码、第三方手录和添加结构均嵌在相应步骤。设备详情默认收起；公共型号资料一次展示，逐台记录身份与差异。参数默认显示必要设置和异常，完整依据/高级参数按需展开。不能仅用红黄绿表达结果，必须同时给出中文状态。

拓扑来源于 L1 框架，并随 L2-L5 保存逐步补全。电气图表达电气连接，通信图表达通信路径，逻辑控制用不同线型。规划、已录入、现场验证三种来源分开，遥测覆盖层必须标明模拟/现场和时间。M1 图仅缩放查看，滚轮默认滚动页面，缩放使用明确按钮，避免锁住上下滚动。

每条提示采用统一结构，例如：“光伏总线 A 的校验方式缺少 GT3 对应固件依据；由厂家确认；阻断该总线参数写入；可继续编辑其他设备；点击打开步骤07 / 总线 A / 校验方式”。同一根因影响 10 台时合并提示，展开后能定位每台。

## 17. 数据、规则与配置状态约定

### 17.1 核心数据对象

工程模型保存项目、结构、型号版本、资产、端口、连接、总线、数据映射、控制域、参数集、依据和待办。部署基线与配置任务是独立对象；遥测和测试结果不回写为厂家主数据。

每个参数至少包含：对象 ID、参数键、适用条件、单位、计划值、批准值、现场实际值、实际值来源/时间/质量、厂家约束、风险等级、依据引用、批准状态和版本。空值表示未知；“不适用”必须有条件和理由。读取值不自动覆盖计划/批准值，改为采用实际值须产生明确变更记录。

模板和驱动记录供应方、版本、状态、支持型号/固件范围、能力字段、读写范围、换算规则及依据。草稿可用于明确标识的模拟，不能作为现场写入依据。型号或固件改变时重新计算适用性，不能静默继承旧批准。

### 17.2 状态分开保存

| 状态维度 | 示例 | 不可混淆的含义 |
| --- | --- | --- |
| 工程编制 | 草稿、已保存、已冻结 | 已保存不等于已批准 |
| 依据适用性 | 待 EPC 补充、待厂家确认、适用依据齐备 | 资料上传不等于批准有效 |
| 部署执行 | 未下发、执行中、部分成功、已完成、状态未知 | 回执成功不等于实际一致 |
| 读回一致性 | 未读回、一致、不一致、不支持、已过期 | 不支持读回不能显示一致 |
| 策略激活 | 未激活、已激活、未知 | 参数存在不等于策略正在执行 |
| 测试与验收 | 由 M2/M3 分别记录 | M1 不输出 SAT 或验收通过 |

### 17.3 校验与权限

校验覆盖结构引用、必填依赖、端口兼容、身份唯一、总线地址、驱动适用、计量换算、运行约束和批准依据；规则包本身有版本。纯格式检查可即时执行，涉及设备兼容性的判断必须有资料依据。所有阻断都关联对象、字段、原因、责任方、影响动作和定位目标。

配置写入由 iEMS 后端授权和审计，不能只依赖前端禁用按钮。控制器端执行并持久化任务，具备请求去重、并发版本校验及重连查询。设计不要求设备天然支持事务、回退或原子激活，能力不足必须反映到执行计划。

SIMULATION 与 REAL 的基线、任务、证据和交接链分别隔离。允许把模拟工程模型复制为现场草案，但必须清除模拟身份、批准、部署与验证状态，再重新核实。离线编制允许本地保存受控草案；离线编辑不自动同步写入现场。

## 18. 参考项目走通示例

本例为设计验收样例：10 台 LIVOLTEK 125 kW 并网光伏逆变器、10 台 125 kW / 261 kWh 储能、1 台 iEMS、PCC 零馈表、交换机以及 EPC 定义的配电/汇流/开关。按题设标称容量合计 PV 1.25 MW、BESS 1.25 MW / 2.61 MWh；实际产品容量以扫码获得的适用型号数据为准。

单台 iEMS 管理 20 台主设备是本例项目方案，不把它当成所有 iEMS 型号的容量保证。电表、网关、辅助设备是否计入节点上限，以及 20 台设备所需轮询负载，必须由相应型号/固件能力包确认。通信方式亦为示例选择，最终从设备资料确定。

| 顺序 | 本例执行 | 可观察结果 |
| --- | --- | --- |
| 01-02 | 选择模拟环境、单 PCC 并网零馈场景 | 一个 iEMS 控制域，生成主配电、光伏、储能框架 |
| 03 | 按 EPC 输入建立主母线与两类汇流回路 | 未提供的开关规格显示待 EPC 核定 |
| 04 | 扫码登记 20 台主设备；用模板手录零馈表和交换机 | 型号合并，逐台 SN/固件独立；第三方依据单独标识 |
| 05-06 | 录入电气端口、计量链路及各通信路径 | 系统图自动补全；无第二、第三台 iEMS 虚构节点 |
| 07 | 按实际链路生成总线/网络设置 | 例如已确认 RS485 才出现波特率；以太网设备不显示串口项 |
| 08 | 定义零馈表的 PCC、功率符号和倍率处理层 | 缺少点表时计量映射待确认，不能进入依赖它的控制写入 |
| 09 | 设置零馈、光伏限制与储能边界 | 额定容量与实时可用能力明确分开，未批准策略不可执行 |
| 10-11 | 冻结模拟基线，模拟下发并读回 | 一台设备差异只标该台及相关依赖，不能以其余设备一致代表全组 |
| 12 | 向 M2 提交已确定范围及未完成项 | 模拟调试独立留痕；厂家缺项进入对应步骤，不能自动消失 |

## 19. 开发验收场景

1. LIVOLTEK 扫码成功后厂家字段自动带出且只读；当前固件未知时不显示已核验。无可信主数据时保留待确认。
2. 第三方模板未匹配实际固件时，允许保存草稿，禁止依赖未确认驱动的现场控制配置。
3. 同型号设备批量建立后，SN、站号/IP 和实例结果仍逐台独立；重复地址只按对应寻址域检查。
4. 两端都按先对象后端口选择；只在唯一兼容可用端口时自动选中；保存后拓扑更新且无法在图上编辑。
5. 修改 L1 运行方式或 L3 固件后，适用参数重新计算；旧依据、读回和测试有明确失效范围。
6. 同总线公共参数修改列出全部受影响设备；以太网直连不会出现无关波特率设置。
7. 仪表已输出一次侧值时再次设置 CT 倍率产生明确冲突；未知读数不按零处理。
8. BMS 禁止、SOC 不满足或实时上限未知时，界面不把额定功率显示为已确认可调容量。
9. 缺少降级/恢复依据时，保存为待确认，依赖其安全退出能力的写入/控制不放行。
10. 部署中断后刷新浏览器查询同一任务；回执丢失不重复执行；部分成功保留逐台结果。
11. 读回不支持时显示无法自动核验，允许按批准替代证据处理，但不能标为自动读回一致。
12. 现场身份不符、越权调用、过期基线或并发版本改变时，后端拒绝写入并给出原因。
13. 完成只读接入但控制依据不足时，只能进入对应只读诊断；不能解锁限功率或充放电测试。
14. 模拟切现场后不继承模拟批准或验证结果；M1 修改不能覆盖 M2 会话和 M3 原交接包。
15. 缺项提示点击能打开正确步骤、设备和参数；同根因合并展示，仍能逐台处理；页面可正常上下滚动。
