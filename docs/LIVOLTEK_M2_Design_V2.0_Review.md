# LIVOLTEK Project Engineer M2 引导式安装设计说明书

版本 V2.0｜产品与研发评审稿｜2026年11月7日

适用对象：产品负责人、交互设计师、研发、LIVOLTEK技术支持与EPC工程师。

本文重新定义 M2 的业务流程、页面结构、检查内容、记录与异常机制。核心建议是：以电气、通信、控制三个步骤组织少量现场检查主题；主题内按型号提供共用指导，再关联实际设备与回路逐项留证。拓扑是定位工具，不是任务生成数量的依据。本文为拟议设计，不表示已实现或已获厂家批准；现有 Demo 本次不改动。

## 1 设计结论与当前问题

当前 Demo 已从185条记录合并为40组，但只是压缩了显示数量，尚未重建现场工作逻辑。建议将 M2 重构为“项目点检总览 → 当前检查主题 → 具体对象记录”三个页面层级，异常可从任何层级定位到对象。首页不铺开完整说明、参数表、旧工作包和执行历史。

### 1.1 当前实现的主要问题

| 当前现象 | 为什么造成混乱 | 本版处理 |
| --- | --- | --- |
| 按拓扑边逐条派生点检 | 一条模型连接不一定是独立现场工作；逻辑节点容易重复计数 | 按工程检查目的生成主题，以设备、物理接口、总线或系统功能作为检查对象 |
| 185条记录合并成40组 | 仍按底层数据组织工作，不能直接回答下一步应检查什么 | 固定三步骤；当前示例采用12个候选主题，按实际适用性裁剪 |
| Checklist下仍保留整套旧工作包 | 同一工作有两个入口、两套状态及两种“完成”口径 | 保留旧数据，只读历史入口；新记录仅走统一点检流程 |
| 长说明、厂家缺项、现场结果混在一起 | 用户不知道是在读指导、补资料还是记录事实 | 共用指导、对象记录、资料问题分别展示并关联 |
| 每项一律缺厂家资料 | EPC图纸核对也被厂家缺项笼统阻塞 | 按具体判据区分EPC依据、厂家依据及双方接口依据 |
| 新反馈覆盖当前异常显示 | 原失败改成待确认后可能从异常区消失，未形成真正复核 | 建立独立异常单；状态更新不自动关闭异常 |
| 控制策略核对与动态试验容易混淆 | M2逐渐承担M3工作，边界不清 | M2核对配置和映射；动态控制及系统功能试验由M3承接 |

以上为对本地实现的评估，基于提交7ef2db0及相关设计记录。40组和185条是当前Demo的组织结果，不是设计目标，也不是工程必检标准。

### 1.2 本版优先确定的产品决策

保留导航名“M2 引导式安装”，页面副标题使用“电气、通信与控制现场点检”。用户的主要动作是查看当前检查主题、选择设备或回路、记录事实、处理异常和继续下一项。M2不建立施工计划、班组、工期、安装产值或设备就位管理。

M2退出时形成可追溯的点检记录与未结事项清单，可供M3选择适用测试；不产生“系统正常运行”“允许送电”“合同验收通过”等结论。检查记录齐备与M3具体测试可执行必须分开判断。

## 2 企业做法与适用边界

调研采用厂家官方手册，比较的是流程组织方法，不对企业作综合排名，也不将他厂操作参数套用于LIVOLTEK。资料检索日期为2026年11月7日。以下“可借鉴设计”是本文建议，不是对竞品现有界面的原样描述。

| 企业与资料 | 官方资料可确认的做法 | LIVOLTEK可借鉴设计 |
| --- | --- | --- |
| Huawei FusionSolar SmartPVMS 26.3.0 安装商手册 | 同型号设备支持选择后统一进入参数设置；参数随设备型号变化，具体说明需查对应设备手册；能源管理设置按场景组织 [S1] | 同型号共用指导，场景决定可见内容；逐台事实与批量设置分开 |
| SMA Sunny Tripower X 系统管理器投运流程 | 明确系统管理器与从属设备角色，按规定顺序完成设备接入和配置向导，再进入门户监控 [S2] | 单一项目主控对象、明确前后依赖；安装点检与长期监控分开 |
| SolarEdge SetApp 三相系统安装手册 V1.9 | 区分激活、配置与验证；配置菜单随系统类型变化，另设通信连接及故障处理内容 [S3] | 一步一个明确目的，正常流程简洁，异常时才展开排查内容 |

不照搬的部分：竞品手册中的上电、激活、参数下发、控制试验及产品特定端子要求。本文件不引用其数值作为LIVOLTEK判据，不据此宣称iEMS接入容量或第三方兼容性。企业资料仅支撑本章所述有限观察；后续章节为结合用户需求提出的设计。

## 3 产品定位与模块边界

LIVOLTEK Project Engineer是主设备厂家提供给EPC工程师的系统感知型安装调试辅助、现场故障排查及远程技术支持协同工具。它不取代EPC专业电气设计、施工管理、法定检验或合同验收工具。

| 范围 | M2应提供 | M2不承担 |
| --- | --- | --- |
| 电气 | 与主设备运行相关的接线、接地、计量位置及接口一致性点检 | 电缆选型、保护整定、施工组织或法定电气检验 |
| 通信 | 实物接口指导、线路核对、L5配置对照、满足条件后的只读数据核验 | 无依据针脚推定、任意第三方参数写入 |
| 控制 | 主控权、目标设备、指令与反馈映射、零馈及光储策略配置核对 | 限功率下发试验、充放电切换、并离网切换及性能验收 |
| 技术协同 | 带对象和证据向厂家提出问题，记录技术回复及适用范围 | EPC任务派工、进度考核或厂家代替EPC工程批准 |
| 输出 | 当前版本点检记录、未结事项、M3输入资料 | 系统投运许可、验收证书或运行保证 |

设备与接口资料不足时，可以保存草案和现场观察，但不能生成未经证实的操作要求。真实动作仅由有权限人员在适用条件下使用厂家批准工具执行；当前Demo保持无真实设备连接。

旧基线中的“L1/L2/L3建模深度”与当前M1的“L1至L6工程数据层次”不是同一概念。实现字段应分别命名，例如modeling_depth与engineering_layer，界面不复用相同简称。M1流程仍按当前已确认的L1至L5逐步完善，不重新引入被取消的独立L6检查页面。

## 5 信息架构与主流程

### 5.1 唯一主流程

进入项目 → 载入M1已保存基线 → 电气点检 → 通信点检 → 控制配置点检 → 查看记录摘要与未结事项。

每一步均可查看其他步骤，保存草稿不要求全项目无缺项。继续下一步时提示未完成和依赖项；没有依赖关系的检查可继续。对于具体需要上电、通信读取或厂家明确方法的事项，只阻止受影响操作，不阻止浏览或现场观察记录。

### 5.2 三个页面层级

| 层级 | 主要内容 | 主操作 |
| --- | --- | --- |
| 项目点检总览 | 项目及基线、三步骤摘要、当前待办、异常和资料缺口的数量 | 继续点检 |
| 检查主题页 | 当前步骤主题列表、选中主题说明、适用型号及对象范围 | 进入对象记录 |
| 对象记录页 | 具体设备或回路、端口、适用判据、现场结果和证据 | 保存并查看下一对象 |

主题页与对象记录页沿用同一中央工作区，使用面包屑返回，不叠加多层抽屉，不采用固定左中右三栏。桌面和移动端保持相同流程。展开或导航状态应可恢复；从M1返回时回到原对象、筛选条件和滚动位置。

### 5.3 与M1的数据关系

M1保存设备、结构、连接和系统设置；M2保存点检事实。M2内展示L5计划值、现场值、批准值及来源，均带版本。发现错误时“修改系统设置”定位到L5具体参数；不在M2建立第二份可编辑主数据。现场测得的观察值先属于点检记录，只有用户明确采用并保存M1版本后才成为系统现场配置。

扫码仅用于确认当前实物身份或定位设备。已经在M1录入的LIVOLTEK厂家字段不重复填写；第三方资料缺失时定位L3补充。扫描到不同SN时提示更换或选错设备，不悄悄覆盖资产。

## 6 当前示例项目的检查主题

本项目使用单台iEMS管理10台PV与10台BESS，配套零馈表、CT、网络和相关配电结构。该架构来自用户指定方案。iEMS具体交付型号、固件与20台接入能力仍须厂家资料确认，不能由竞品资料证明。

下表为12个建议主题，不是强制固定模板。型号、实际端口、运行方式和批准依据决定主题及对象数量；缺失信息列为待补对象，不作为“不适用”隐藏。

| 步骤与编号 | 检查主题 | 对象组织与主要输出 |
| --- | --- | --- |
| 电气 E01 | 主设备电气接口与回路对应 | PV与BESS按型号分组，保留设备到批准回路的实际对应关系 |
| 电气 E02 | 保护接地接口 | 对有适用接地要求的设备逐台记录，不对所有资产机械生成PE任务 |
| 电气 E03 | 并网点计量接口 | 零馈表、CT、相别、方向和倍率作为一组计量功能核对；保留各实物对象 |
| 电气 E04 | 外部配电与保护接口 | 核对影响主设备的边界、开关及必要状态接口，引用EPC设计，不审核全厂保护设计 |
| 通信 C01 | 零馈表与iEMS通信 | 两端实物接口、协议/地址和计量数据身份；计量回路接线不重复计算 |
| 通信 C02 | 光伏通信总线 | 总线公共接线和通信格式检查一次，10台PV身份及端口分别记录 |
| 通信 C03 | 储能通信网络 | 交换机及网络公共条件检查一次，10台BESS链路、身份和数据分别记录 |
| 通信 C04 | iEMS接入与网络边界 | 主控网络、必要现场访问路径及时间基准；非必要云接入不阻塞本地点检 |
| 控制 K01 | 主控权限与对象映射 | 单台iEMS及20台目标设备，明确控制来源和反馈对象；不执行指令 |
| 控制 K02 | 零馈控制配置 | 一个系统功能对象，核对计量源、方向、目标、光储协调与失联策略 |
| 控制 K03 | 光伏限功率配置 | 同型号共用说明，10台PV保留各自计划值、现场值及反馈映射 |
| 控制 K04 | 储能运行配置 | 同型号共用说明，10台BESS分别核对模式、功率方向、SOC边界和约束 |

计量CT二次信号属于计量接口，不因为模型将它归入COMMUNICATION边就生成“通信在线”检查。逻辑汇流节点、逻辑控制端口和实体通信端子必须区分；模型分类不足时先提示建模语义待确认。

当前项目名称使用2.612MWh，而“261kWh × 10台”为2.610MWh。本设计不擅自改型号或项目容量；应在M1核对准确型号额定值，再统一容量展示。该差异不产生额外施工任务。

### 6.1 主题不是一张巨型检查表

每个主题最多先显示三类内容：检查目的、当前需要处理的对象、资料/异常提示。详细方法只在进入该主题时出现。对象内部可以有多个原子判据，例如端口正确、线路标识一致、地址不重复；原子判据用于精确记录与判断，不全部提升到首页。

一条原子检查可关联多个模型边。例如PV_01至光伏汇流回路经过逻辑母线与开关时，保留完整路径用于定位，而不是为每段抽象边要求同一张现场照片。反过来，一条物理连接如具有两个必须独立验证的端点，也可以拆分证据要求。

## 7 页面设计

### 7.1 项目点检总览

取消大幅宣传式首屏和重复模块介绍，进入M2即可看到项目、当前基线及“继续点检”。三步骤各显示当前状态、待处理对象数量；首页不把185条底层记录作为主标题或总体进度分母。

异常栏只显示尚未关闭的异常，提供“查看全部”。资料待确认单独计数，不与异常混为一谈。厂家文档缺失以型号或接口归并成一条资料问题，例如“GT3-125K-1限功率接口依据待确认，影响10台”；不重复显示10次相同文字。

页面结构示意如下，文字仅示意，不包含真实通过结果。

```text
项目名称   基线 R6   厂家指导草案                       继续点检
电气点检           通信点检           控制配置点检
需处理异常 2       待厂家资料 3       待EPC补充 1
当前步骤 通信点检
零馈表与iEMS       公共检查待确认      1个对象待处理
光伏通信总线        公共检查已记录     10台中1台异常
储能通信网络        公共检查待处理     10台待点检
iEMS接入与网络边界   待确认
```

主题数量和设备数量必须分别标注。“10台中1台异常”只在真实记录支持时出现。无反馈时显示“未点检”，不显示绿色、100%或“系统正常”。

### 7.2 主题工作页

顶部显示“通信点检 / 光伏通信总线”、适用型号、指导版本和相关资料。主体从上到下为局部图、共用方法、公共检查结果、设备列表。公共检查只对该总线或网络实例生效，不因同协议而跨总线复用。

设备列表使用紧凑行：设备简称、SN尾号、端口或地址、现场结果、资料状态、异常标志、记录入口。完整型号和长名称放在组标题或详情中；不在每行重复“iEMS统一控制20台”等文字。只展开一个对象编辑区，保存后提供“下一待处理对象”。

公共配置异常时，在主题顶部提示其影响范围；未验证的10台设备显示“受公共条件阻塞”，不能自动全部标为“设备故障”。公共问题解除后，逐台检查仍需完成。

### 7.3 设备或回路记录页

对象身份、源端设备及端口、目标设备及端口置顶。仅展示当前对象适用的差异参数和判据；共用说明可返回查看，不复制长文。记录区包含现场结果、实际观察/读数、单位、记录人、时间和需要的附件。

有实测要求才显示仪器和测量记录；照片要求由模板决定，不要求所有项目至少上传一张照片。异常需填现象和影响对象；不适用需填原因并按风险决定是否复核。记录人来自已登录身份，代录时区分操作人和实际检查人。

### 7.4 图形辅助

图从已保存L4生成；总图只显示一台iEMS。物理通信连接展示设备、工程端口、已核验实物端子及线缆类别；缺少实物定义明确标注待厂家确认。控制关系用独立逻辑图或明显不同图例，不能画成另一根待施工线缆。

在当前主题默认仅显示相关路径，提供“查看系统总图”。图只读，不允许拖动节点或改线。点击连接在图下展示信息并定位检查对象，不用悬浮大面板遮图。本版不重新加入已经撤回的缩放、全屏及端口高亮方案；相关查看能力另行评审。

## 8 分组与任务生成规则

### 8.1 正确的生成顺序

读取L1运行方式及相关系统范围，匹配检查主题；读取L3型号与受控指导，确定适用方法；读取L2与L4建立实际检查对象及路径；读取L5生成应核对的设置与偏差；最后生成对象级原子检查和展示分组。不能从“遍历所有边”开始直接形成首页清单。

### 8.2 允许共用指导的条件

同型号、主数据版本兼容、固件适用范围兼容、相同检查目的、相同接口域与方法、同一指导及判据版本时，可以共用说明。两台设备的具体设置值不同不一定拆组，但差异必须逐台显示；若差异改变检查方法、风险、判据或前置条件，必须拆组。

仅名称相同、node_type相同或都标为“第三方”不构成合并依据。缺型号的资产保留独立身份。无SN结构对象可按检查主题归类，但每条具体回路保留额定参数与设计引用，不推断规格相同。每个检查实例有稳定ID，多视图引用同一实例，不重复生成完成状态。

### 8.3 批量操作的界限

允许批量关联同一厂家文件、复用已确认的公共指导及筛选同型号设备。不提供“一键全部通过”。批量填入公共设置只能在L5的适用规则下进行，不能变成M2逐台核验结果。照片可关联同一真实场景中的多个对象，但每个对象必须明确标识；不自动复制照片证明未拍摄设备。

### 8.4 分母与状态汇总

首页显示主题级待办，不计算施工进度。主题内分别显示公共检查与逐台检查，例如“总线公共检查1项待确认；10台设备，8台已有记录、1台异常、1台未检查”。这些数字按同一版本下有效实例计算；已批准不适用单独列示。不能把“已有反馈8台”显示为“通过8台”。

## 9 状态与异常机制

### 9.1 三条独立状态轴

| 维度 | 建议状态 | 含义 |
| --- | --- | --- |
| 现场记录 | 未点检、已记录待判定、符合、异常、不适用待确认、不适用已确认 | 描述对象的观察及判定，不代表厂家文档状态 |
| 依据 | 已核验适用、待厂家确认、待EPC补充、版本失效、不适用 | 描述该条判据的依据充分性 |
| 问题处理 | 开放、处理中、待复核、已关闭、重新打开 | 描述异常或资料问题是否真正解决 |

“符合”要求该条适用判据和必要证据齐备；如果判据尚不明确，可以记录现场事实但只能显示“已记录待判定”。对纯EPC图纸一致性核对，不强制增加并不适用的厂家批准；对产品专属参数及接口要求，不能以EPC填写文档编号替代厂家确认。

### 9.2 异常闭环

首次异常产生独立问题ID，带原记录、对象、项目基线、影响范围、责任方和证据。提交新反馈不会删除旧异常。处理人为问题提出处置，复核人依据新证据关闭；是否允许同人复核由风险规则决定。厂家回复“资料已提供”只能解决资料问题，不能自动证明现场接线已正确。

顶部默认显示阻塞当前工作的未结问题，再显示其他未结问题。把结果改为“待确认”不能让失败问题消失。不适用必须有理由；安全相关或接口关键项需负责人确认，不能用“不适用”绕过点检。

### 9.3 下一步提示与可执行性

浏览下一步骤不等于完成当前步骤；提示应包含明确数量和对象入口，不弹出笼统“资料不完整”警告。资料缺失只影响相关检查。需要真实读取或现场试验的项目，执行入口必须显示其具体前提与授权状态；本期仅提供记录和引用，不提供动态试验执行按钮。

## 10 厂家依据与参数展示

每条指导至少有文件ID、版本、页码或章节、适用型号、固件范围、语言、提供方、核验人、核验日期及状态。厂家确认的是产品资料及适用性；EPC批准的是其设计和现场工程事项，两者分别保存。

通信参数按L4接口域出现。RS485显示地址及适用串口格式，以太网显示适用的寻址、地址和业务协议；不要让所有设备同时填写两套字段。型号默认值只有在受控来源支持时才带入，并显示来源；第三方优先使用已核验模板，否则提示手录。总线公共参数核对一次，站号仍逐台检查唯一性。

控制主题只展示与当前运行方式相关的参数。零馈主题显示目标、计量源、符号约定与异常策略；PV显示适用的限功率配置；BESS显示充放电方向、模式及适用边界。单位、计划值、现场值、批准值和文档依据不得合并成一个“正确值”。缺依据时不猜测响应时间、容差、SOC阈值或默认通信格式。

## 11 数据与接口设计

### 11.1 核心对象

| 对象 | 关键字段 | 约束 |
| --- | --- | --- |
| InspectionSession | project_id、baseline_id、model_hash、catalog_version、created_by | 固定模型与指导快照；不因页面刷新重建 |
| InspectionTopic | topic_id、stage、purpose、applicability、dependencies | 表达现场检查目的，不等于拓扑边 |
| InspectionInstance | instance_id、topic_id、target_refs、criterion_refs、scope_key | 关联设备、物理接口、总线或系统功能；防止重复派生 |
| GuidanceSnapshot | document_ref、version、applicability、method、criteria、evidence_policy | 当前记录可追溯到当时的指导，而非只读最新文本 |
| Observation | observation_id、instance_id、actor、observer、result、values、evidence_refs、timestamp | 追加式保存；实测值含单位及质量，不覆盖原记录 |
| Issue | issue_id、instance_refs、type、owner、state、resolution、review_refs | 异常与资料问题独立生命周期，不能靠改结果隐藏 |
| DisplayGroup | group_key、instance_refs、shared_guidance_ref | 仅展示分组，不拥有可批量通过的结果 |

### 11.2 建议接口行为

沿用现有项目、模型和照片接口能力，新增或调整点检会话、主题、实例、观察及问题接口。会话创建使用幂等键，避免重复点击生成多套工作；观察提交使用客户端请求ID防重。所有写入校验对象归属、基线版本和权限；不能只依赖前端禁用按钮。

查询主题时返回公共条件、逐台摘要和未结问题；进入对象时再加载完整证据及历史。照片保存对象归属、上传人、时间和校验值；未完成上传不能计为证据齐备。未登录身份、跨项目附件和过期会话写入均应被拒绝。

### 11.3 模型变更与记录继承

M1变更后计算影响，不简单清空全项目记录。例如修改PV_03地址，只重开对应通信核验及依赖项；更换零馈表型号，重开计量接口、协议和依赖的零馈配置核对。布局调整不使电气记录失效。受影响范围不能确定时保守提示复核，并说明原因。

旧记录仍可查看，不能静默移动到新对象。只有对象身份、相关模型指纹、指导版本和判据均满足继承规则时，才可以明确标示“沿用原记录”，并保留来源。第一期可采用受影响对象人工复核，不能以“全部清空重做”冒充影响分析。

### 11.4 网站与现场使用

第一期采用响应式网站，弱网时保留当前未提交表单并显示保存失败及重试，不显示虚假成功。离线缓存、照片队列、冲突合并和加密暂存作为第二期独立能力，未实现前不承诺完整离线点检。移动端提供单对象记录、拍照及下一对象入口。

## 12 页面迁移与交付顺序

### 12.1 现有Demo处理

保留M1、模型、单台iEMS方案、已保存端口连接、现场照片及历史结果。将旧工作包、安装台账、正式发布门禁演示和历史执行记录移出M2主工作区，放入明确的历史资料入口。迁移不删除原计划，也不把旧“安装完成”转换为新“检查符合”。

现有40组仅为迁移输入，不能直接成为最终主题目录。原item_id通过映射表关联新实例；无法确定映射的历史记录标为“待人工关联”，可追溯但不计入新主题完成。旧“FAIL后来改PENDING”的记录须恢复为待复核问题，而非按最后状态丢弃。

### 12.2 分阶段实施

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| A 页面与主题模型 | 12个候选主题、三层导航、旧功能收纳、设备行精简 | EPC可准确找到下一检查对象，首页不出现40组长清单 |
| B 记录与问题闭环 | 公共检查和逐台结果、证据规则、独立异常单、精确返回 | 异常不因切换状态消失，同型号结果互不污染 |
| C 依据与版本治理 | 指导适用性、判据来源、M1影响分析、M3资料输出 | 能说明每项结论的依据、版本及剩余限制 |
| D 现场能力增强 | 弱网与离线、批准的只读设备集成、技术协同深化 | 单独完成功能及授权验收，不与页面改版捆绑承诺 |

厂家技术协同需求以问题或资料请求关联，不自动扩展为施工计划或资源排班系统。如果后续建设独立厂家技术协同计划，应作为明确的新需求设计。

## 13 验收用例与设计评审重点

| 编号 | 场景 | 必须看到的结果 |

| U01 | 打开当前CI-20项目 | 三步骤及适用主题，底层记录数量不主导首页 |

评审采用真实EPC任务走查：定位零馈表接口问题、完成一台PV核对、处理一台BESS异常并返回原位置。建议目标是首页最多三步导航和当前步骤四个主题入口、进入对象记录不超过两次业务选择；主题数量随项目适用性变化，不为满足数量目标隐藏检查。
