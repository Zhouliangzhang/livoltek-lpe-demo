# M2 步骤14与M3：封存资料及项目交接

## 实现范围

步骤14核对步骤13报告与当前项目、配置基线、会话及环境一致后，将配置、01–12步骤结果、报告快照、原始证据和遗留事项一起封存。报告缺失、过期、跨项目/会话/环境或证据校验不一致时阻断封存。模型有未保存修改时前端禁止发起新封存。

允许携带未完成项进行资料归档。资料编制人确认的是资料及遗留事项随包移交，不是SAT签署或验收批准。模拟包状态为SIMULATION_ARCHIVED；现场环境目前仅支持FIELD_DRAFT_ARCHIVED资料草稿，未执行现场交接，field_accepted及sat_passed始终为false。

封存采用不可变SQLite记录与幂等请求ID。再次测试或修改配置不会改写旧包，列表提示已非当前依据；须保存新报告再形成新包。重试原请求仍返回原封存记录。

未完成步骤、当前未关闭设备异常、待EPC补充与待厂家确认项原样带入。主题合并展示，逐对象定位M1设备/参数，或返回同一调试依据与会话的对应步骤。定位处理打开工作区，封存包保持不变。厂家协同仅生成草稿，不自动发送；没有直接勾选关闭问题的入口。

## 导出及校验

ZIP包含baseline.json、test-results.json、sat-report.json、sat-report.html、evidence.json、followup.json、manifest.json及README.txt。报告HTML在封存时固定，下载时不重新生成当前内容。

各组件及封存主体采用SHA-256校验：JSON键排序、UTF-8、ensure_ascii=False、分隔符为逗号及冒号且无空格。组件包括完整模型及视图布局，不使用工程语义哈希的字段排除规则。封存主体校验不含数据库生成的id/kind/project/created及请求字段、seal_hash本身。校验值用于内容一致性验证，不是电子签名。
