# iEMS 工程工作台调试与 SAT 设计文件

文件编号：LIVOLTEK-IEMS-M2-DESIGN-001  
版本：V1.0  
日期：2026年11月8日  
文件状态：设计评审稿  
适用读者：产品、iEMS研发、设备研发、测试、厂家技术支持及EPC调试负责人

本文件定义 iEMS 工程工作台 M2 的完整产品与执行设计。现场工程师确认测试条件和授权，iEMS 内嵌测试程序按依赖顺序执行，工作台呈现设备实际响应、自动判定和异常定位。完成一个步骤并取得有效证据后，才开放依赖它的后续步骤。现场 SAT 依据项目批准的测试规程及签署权限形成结论。

本文件为独立新设计，不以现有页面、原有模块结构或已有演练功能作为约束。文中的功能均为目标设计要求，不表示已经实现或已经获得厂家批准。

## 1 产品定位和执行边界

### 1.1 四个模块的分工

M1 系统建模与设置形成工程模型及预期配置；M2 调试与 SAT 验证实际设备、实际配置和实际控制效果；M3 项目交接接收已冻结的配置、测试证据、限制条件及签署记录；M4 现场服务承接投运后的诊断、厂家协同和变更后的复测。

工程工作台是 iEMS 的工程功能界面。iEMS 是现场测试的执行主体和结果事实来源；浏览器负责展示、授权和交互，云端负责受控协同、资料和归档。浏览器关闭、刷新或互联网中断不得使现场测试失去本地约束。

本期主路径面向并网光伏与储能系统，重点验证零馈计量、设备通信、功率控制、系统联动、降级及恢复。离网、黑启动、并离网切换、发电机、无功及电能质量等能力，仅在项目模型启用且具备适用设备、厂家规程和测试条件时生成专用分支。未配置的能力不能通过普通并网测试获得证明。

### 1.2 自动执行与人工职责

| 主体 | 在 M2 中的职责 | 不应由其自动替代的事项 |
| --- | --- | --- |
| iEMS 测试程序 | 读取、识别、受控下发、反馈核对、计时、停止、留证与恢复状态管理 | 专业电气设计、法定试验、物理接线质量确认 |
| EPC 现场工程师 | 确认作业许可、可测试范围、现场条件和实物对应关系；处置现场问题 | 不得用手工打钩覆盖自动测试失败或缺失遥测 |
| LIVOLTEK 厂家工程师 | 发布适配型号与固件的驱动、测试包、限值及处置指引；协同分析 | 不代替EPC确认施工质量或签署合同验收，除非有相应合同授权 |
| 第三方设备厂家 | 提供点表、接线、控制限制和异常行为依据 | 未经验证的第三方模板不视为批准驱动 |
| 项目授权见证和签署方 | 确认 SAT 范围、见证、偏差接受与结果签署 | 平台自动判定不代替其验收权限 |

安装准备、设备就位、施工进度及资源安排不进入 M2 工作流。M2 仅引用 EPC 已完成的必要电气检查、接地和上电条件等外部记录，作为执行前提。引用记录不等于平台重新检验这些工作。

### 1.3 借鉴方法及其适用范围

SMA 的 System Manager 调试流程要求明确唯一系统管理者，先处理所属设备，再由统一界面完成系统配置。本设计据此明确一个控制域一个有效指令所有者，并以配置向导串联测试依赖。[S1]

华为 SmartLogger 手册提供部署向导，以及设备参数、现场测试和设备日志等功能组织。本设计借鉴“控制器内统一调试入口”，将设备识别、配置、执行和证据关联起来，不推断其具有本文件设计的全部自动测试能力。[S2]

Victron ESS 调试指引先确认设备显示及控制状态，再通过适用运行场景验证预期行为。本设计据此区分通信在线、控制有效和系统运行效果三个层次。[S3]

Schneider Electric 的 Conext XW+ 调试清单按前置检查、上电配置、设备运行测试及调试后工作组织。本设计借鉴其顺序和收尾记录方法；其2015年设备清单仅作为流程参考，不作为当前产品参数依据。[S4]

SMA 的零馈控制说明同时涉及 PCC 计量和兼容设备的通信失效后备行为。本设计据此要求单独验证计量可靠性与本地降级能力，不把“指令发出”当成失联设备已降功率。[S5]

以下具体步骤、数据结构、界面及恢复状态机是本文件提出的设计方案。其他厂商做法不能直接作为 LIVOLTEK 控制时延、功率容差、SOC边界或失联策略的证明。

## 2 严格按调试顺序组织的主流程

### 2.1 顺序总览

| 顺序 | 调试步骤 | 完成后才能证明什么 |
| --- | --- | --- |
| 01 | 建立调试会话与冻结依据 | 测试对象、范围、权限和依据明确 |
| 02 | iEMS 自检及控制权确认 | 本地测试引擎可用且不存在竞争控制 |
| 03 | 零馈表通信与计量验证 | PCC反馈可信，可以用于控制判断 |
| 04 | 光伏通信与身份验证 | 每台光伏可正确识别和读取 |
| 05 | 储能通信与可用能力验证 | 每台储能可识别，充放电边界可读取 |
| 06 | 配置下发与实际读回 | 实际生效配置与批准基线一致 |
| 07 | 光伏逐台受控测试 | 每台光伏能接受并执行限定范围指令 |
| 08 | 储能逐台充放电测试 | 每台储能在允许边界内响应且可复位 |
| 09 | 系统稳态联动测试 | iEMS能协调设备实现约定并网点目标 |
| 10 | 动态响应测试 | 在规定扰动与能力范围内满足响应判据 |
| 11 | 异常降级与恢复测试 | 故障可识别，降级可验证，恢复不误解除 |
| 12 | 恢复正常配置并连续观察 | 测试临时设置已退出，运行基线稳定 |
| 13 | SAT 见证复核与签署 | 约定范围内的现场验收证据和结论完整 |
| 14 | 封存并移交 M3 | 形成可追溯、可复用的项目交接包 |

主路径依次开放。工程师可以查看后续步骤的要求，但不能越过阻断条件执行有功率影响的测试。允许在当前步骤内对相互独立的设备进行受限并发只读检测；同一总线通信负荷、驱动限制及读取时序由 iEMS 管理。逐台控制测试默认串行。

### 2.2 每步使用同一执行闭环

进入条件核验 → 展示测试动作与影响 → 取得所需授权 → iEMS执行 → 核对指令确认和实际响应 → 自动判定 → 撤销临时设置并确认退出状态 → 保存证据 → 开放下一步。

失败后必须先进入该步骤定义的退出状态。修复后重新生成一次执行记录，保留失败记录。涉及共享计量、总线、控制权或模型变化时，重新核验所有受影响的依赖步骤。完成率不能代替步骤放行判定。

### 2.3 模拟和现场的隔离

模拟、硬件在环及现场三种环境分别保存会话、设备标识和证据。模拟展示“模拟满足判据”，现场展示“现场测试通过”；硬件在环标明真实接入部分和模拟部分。任何模拟量不得填补现场缺失值，也不得写入现场 SAT 的通过统计。

现场未知数据按“未知”处理，不替换为0、最后有效值或模型估计值。曲线可展示估计或模型值，但必须与有效测量分轨标识，且不参与未获批准的现场通过判定。环境切换须结束当前会话，重新核验控制器身份和权限。

## 3 步骤01 建立调试会话与冻结依据

**进入条件。** M1 已形成可用于本次范围的配置基线。EPC 提供必要安装检查、上电及作业授权记录；设备已按各自适用规程具备通信和调试条件。M2 不负责安排上电作业顺序。

**工程师操作。** 选择现场 iEMS、测试范围、见证要求和批准规程；确认当前项目及控制域。界面列出将受测试影响的设备与回路，不要求重新录入 M1 内容。

**iEMS自动核验。** 绑定控制器序列号与站点身份；冻结 M1 模型哈希、设备型号/SN/固件、端口与连接、配置版本、驱动版本和测试包版本。按本次范围计算必要字段和依赖；只把会阻止本步骤或后续动作的缺项列为阻断。

**放行与记录。** 范围、授权、测试包适用性及本次必需依据齐备后进入02。缺少现场数据定位到M1相应对象；缺少型号或固件依据生成厂家确认项。允许先做已具备依据的只读诊断，但不能据此放行依赖缺失依据的控制测试。

**界面。** 顶部仅显示项目、真实或模拟环境、iEMS身份、配置版本和一致状态。步骤卡显示“还缺什么、谁补充、为何阻断、点击处理”。

## 4 步骤02 iEMS 自检及控制权确认

**进入条件。** 会话和本地身份绑定成功。目标设备处于项目规定的可诊断状态。

**iEMS执行顺序。** 检查引擎、驱动、存储、时钟、日志及本地状态持久化；发现并核对通讯接口和地址；读取控制模式及指令所有者；检查上层EMS、设备本地策略、定时任务是否与本次控制测试冲突；建立本次测试的控制租约与范围约束。

通信引导配置仅限已批准的端口、总线和网络设置。在不会改变运行控制策略的范围内实施，并记录修改前值和生效读回。发现的未知设备先作为候选，不自动加入控制组。换机或SN不符必须回到M1确认。

**判据。** 本地执行与证据存储正常；时间质量满足所选测试要求；每个控制域只有一个有效指令所有者；已知冲突策略按批准程序协调。没有远程写权限时仍可完成允许的只读诊断，但有功率影响的测试保持锁定。

**停止与恢复。** 指令所有权丢失、引擎重启或日志无法持久化时停止发出新测试动作，进入预先批准的退出策略。浏览器恢复连接后查询原运行ID，不能重复启动同一动作。

**输出。** 控制权记录、接口清单、自检结果、时钟偏差及质量、初始运行快照。

## 5 步骤03 零馈表通信与计量验证

**为何优先。** PCC计量决定零馈方向和系统反馈。在计量位置、符号与倍率未确认前，不允许利用其开展闭环控制测试。

**读取 M1。** 零馈表型号、SN、固件、安装位置、计量覆盖范围、CT/PT倍率、相序，以及“零馈表设备及端口 → iEMS设备及端口”的实际连接。RS485路径显示地址、波特率、校验、停止位；以太网路径显示所需IP、端口及协议信息。物理端子不以逻辑端口名称替代。

**执行顺序。**

1. 根据批准驱动读取身份和通信状态，核对实际设备与模型映射，检测重复地址、超时及错误帧。
2. 连续采集三相电压、电流、有功功率、总功率、频率及数据质量；记录源时间或采集时间，不把轮询成功当成数据已更新。
3. 核对单位、符号、比例、总量与分相关系，检测冻结值、越界、跳变、重复数据及时间倒退。设备不提供质量字段时，由驱动给出可验证的质量推导及其限制。
4. 工程师按批准程序，在已知购电状态下以独立参考仪表或可信参考测量确认PCC位置、倍率和方向。iEMS将同步实测量与参考证据关联。不得仅用自身同源数据自证正确。
5. 在不依赖未验证闭环的条件下，确认可用计量窗口和稳定性；不能建立方向参照时标记“证据不足”，不得自动通过。

**判据。** 设备和计量范围正确、数据新鲜、方向与倍率证据一致，误差与持续时长符合本项目批准判据。反向送电验证仅在允许出口和专门批准条件下进行；不为验证符号主动制造未许可馈网。

**异常定位。** 通信故障定位L4连接和总线；型号/点表不匹配定位L3；符号、倍率或计量范围不符定位L5和相关L2对象。显示“两端端口、实际值、期望值、依据、下一处检查”，不得直接诊断为某一实物接线错误。

**输出。** 原始计量片段、通信质量、参考证据、接线确认附件、有效点表及计量映射。后续任何更换表计、倍率或映射的操作均使相关结果失效。

## 6 步骤04 光伏通信与身份验证

**进入条件。** PCC验证完成，光伏设备已按自身规程具备通信条件。

**执行顺序。** 按通信路径发现设备；逐台核对型号、SN、固件和逻辑位置；读取有功功率、可用功率或其受限信息、运行状态、当前限功率值、远程控制权限、告警及本地失联配置；验证数据刷新和单位转换。

**判据。** 每台设备存在唯一映射、具备适用驱动、所需字段有效。单纯Ping成功、读到一个寄存器或一台代表设备通过，不等于全组通过。能力字段无法读取时按厂家批准的替代证据处理，否则依赖该能力的测试阻断。

**界面。** 同型号且同固件适用范围的设备合并为一个主题，如“光伏通信与身份，10台”。主题说明只展示一次，展开逐台结果。固件或驱动适用性不同则拆组。异常设备置顶，保留该台路径和错误证据。

**输出。** 实际设备清单、能力清单、通信质量和待处理映射。单台异常可继续读取其他设备，但系统范围内必需设备未解决前不能进入全系统控制测试；缩小范围须重新建立明确的受控测试范围。

## 7 步骤05 储能通信与可用能力验证

**执行顺序。** 核对每台BESS、PCS及BMS身份关系；读取SOC、SOH（若适用）、温度、运行模式、充放电允许、实时充放电上限、告警、接触器/互锁等所需状态；验证充放电符号、单位及更新时序。

“系统额定125kW”不等于当前允许充电125kW。iEMS必须以设备有效反馈和批准约束计算实时可用能力；通信中断或BMS状态未知的设备不能继续计入可调容量。控制器不能覆盖电池本地保护。

**判据。** 设备映射和数据质量合格；取得后续测试需要的充放电边界、SOC范围及互锁依据。只允许单向运行的设备按实际能力生成测试范围，不能将未测试方向标为通过。

**异常定位。** 区分通信不可达、点表不兼容、BMS禁止、SOC条件不足、设备故障与未知原因。SOC不适合当前测试时标为“条件未满足”，不直接判定设备故障，也不建议绕过BMS。

**输出。** 每台储能实时能力快照、限制原因、保护状态与通信证据，供07至11的动作前复核使用。

## 8 步骤06 配置下发与实际读回

**进入条件。** 必需设备已识别，配置内容和适配关系明确。写操作所需授权及设备状态满足要求。

**执行顺序。** 比较M1批准值与现场读回值；展示差异和影响；保存修改前快照；在批准的非激活或受控模式下写入目标配置；读回并核对实际生效值；确认iEMS与设备的控制参数兼容。需要重启或物理操作的参数转人工停点，禁止后台自动重启。

配置包括总线/网络参数、计量映射、功率符号、设备额定与可用边界、零馈目标、光伏限功率、储能SOC和充放电范围、策略优先级、指令超时、本地失联后备及恢复授权。只处理适用参数，不一次性展开所有可能字段。

**判据。** 关键配置读回一致，或差异有批准的单位换算/量化容差依据；“发送成功”“设备应答成功”和“生效读回一致”分别记录。无法读回的关键配置须有批准的替代验证，不以写应答补足。

**失败处理。** 部分写入失败时停止后续激活，逐项标明成功、失败和未知。按设备能力执行已批准的回退或保持策略并再次读回；不能承诺跨设备原子回滚。未确定最终实际值时禁止进入07。

**输出。** 参数差异、写入事务、应答、读回值、来源、批准依据和最终配置摘要。系统闭环仍待09受控激活。

## 9 步骤07 光伏逐台受控测试

**进入条件。** 计量、配置和控制权有效；具备实际可验证的光照、负载或批准吸收能力；每台测试的初始功率、最小变化量、功率上限、变化速率、时间窗、终止条件和退出状态已批准。

**执行顺序。**

1. 每台开始前重读PCC、设备状态、可用功率和其他设备状态，确认本次动作不会超出测试边界。
2. 先在批准范围内降低有功目标，记录命令ID、设备应答、设定读回及实际有功变化。
3. 实际响应满足判据后，才在批准范围内测试恢复或提高目标；全过程受站点功率边界约束。
4. 退出测试覆盖值，确认该台回到批准状态，再测试下一台。

**判据。** 目标送达、语义正确、响应方向正确、误差和时间满足适用判据，且退出状态可确认。没有足够光照或本来已受限，无法辨别调节效果时标为“证据不足/条件未满足”，不得因输出很低而判定限功率通过。

**异常处理。** 区分指令拒绝、接受但不响应、应答丢失、模式冲突和能力不足。通信超时后不得盲目重发可能重复生效的控制动作；先查询状态。共享PCC、控制权或边界异常立即终止整个控制批次。

**界面与输出。** “光伏限功率”只展示一套说明，逐台显示请求、实际功率、响应时间、退出状态及曲线；通过必须落实到每台设备。

## 10 步骤08 储能逐台充放电测试

**进入条件。** 采用与07相同的控制保护条件，并实时满足该台BMS允许、SOC和功率边界。

**执行顺序。** 读取初始状态 → 在批准小功率范围内充电 → 核对指令、方向和实际响应 → 回到批准中性状态并验证 → 在具备站点负载及允许条件时放电 → 再次复位并确认退出。若型号规程要求不同顺序，以该型号的批准步骤替代，并保留相同前后依赖。

**判据。** 两方向分别记录，不合并成一个“储能通过”。实时限值变化时自动缩小或停止动作；不能为了完成测试增加SOC极限或忽略温度限制。功率符号用页面明文表示“充电/放电”，同时保留协议原值与换算值。

**异常处理。** BMS正常拒绝越界命令属于限制生效的证据，不代表所有控制测试通过。未达到测试工况、设备拒令和保护动作分开归因。停止后以读回确认退出，不把“停止指令已发”视为功率已经归零。

**输出。** 每台两方向响应、动态限值、保护/限制原因、SOC起止、能量及退出状态。实际能量不足以完成整个批次时暂停，并明确尚未覆盖设备。

## 11 步骤09 系统稳态联动测试

**进入条件。** 全部纳入范围的设备完成必要逐台测试；PCC与控制权有效；系统配置已批准且读回一致。确认单一iEMS对本控制域执行功率分配。

**按以下顺序执行。**

1. 在受限功率范围激活系统策略，核对PCC方向、目标和设备总量关系。
2. 光伏富余且储能可充：验证储能吸收、光伏分配和PCC目标跟踪。
3. 储能可用充电能力不足：验证iEMS依据有效能力重新分配并限制光伏，不让剩余设备越限。
4. 负载增加且储能可放：验证放电配合、SOC边界、购电限制及禁止馈网约束。
5. 验证策略切换、计划时段或外部指令优先级中本项目实际启用的项目，最后回到批准基线。

**判据。** 明确按PCC三相合计或逐相判定，不能用合计购电掩盖要求逐相禁止的馈网。曲线同时显示PCC有效实测、目标、光伏实际、储能实际、可用能力和策略状态。功率平衡含已定义的计量边界、损耗及误差，不强求不同计量点数值完全相等。

系统动作效果以PCC及设备反馈共同验证。每项场景都有前置工况证据和稳定窗口；自然工况没有出现则记“未覆盖”，不以模拟替代。储能容量只是辅助约束，不能作为失去计量时保证零馈的依据。

**输出。** 各场景的控制分配、设备响应、PCC实测、稳定误差、约束命中及覆盖范围。

## 12 步骤10 动态响应测试

**进入条件。** 稳态联动通过；批准扰动幅度、动作对象、采样能力、响应判据和现场可用测试手段。不得默认直接操作厂区负荷或拉闸制造扰动。

**执行顺序。** 先验证受控的小幅度扰动；再按批准程序依次验证负载变化、光伏可用功率变化、储能充电能力降低；每个场景恢复并稳定后才进行下一场景。自然扰动可作为证据，但必须证明实际幅度和时间覆盖了测试要求。

**记录与判定。** 同一时间轴保存扰动源、PCC测量、计量质量、iEMS分配、每台指令确认、实际功率和能力变化。分别计算检测延迟、动作延迟、峰值偏差、稳态误差、整定时间、馈网持续时间和馈网电量；各指标适用性及阈值由批准规程定义。

响应计时从可追溯的实际事件起点开始；如只能确定事件区间，则记录不确定度。采样率和时间同步能力不足以分辨判据时，结果是“证据不足”，不得由插值或平滑曲线制造通过结论。缺测时间段不得直接计为零馈网。

**退出。** 越过批准边界、计量失效、能力不足或控制权丢失时停止扰动并进入已批准退出策略。保留失效前后记录，不通过删除异常片段改善指标。

## 13 步骤11 异常降级与恢复测试

### 13.1 先确认测试方法再执行故障场景

本步骤包含可能影响现场功率和保护的动作。每个场景必须声明采用模拟、硬件在环、厂家支持的测试接口或现场批准方法。模拟默认可演练；现场故障注入默认关闭，只有存在适用规程、授权、独立保护和终止条件时才开放。不得指导现场随意拔线、改寄存器或制造拒令。

对不能安全实施的场景，可引用批准的型式/工厂/硬件在环证据并记录适用性；仍须按合同判断能否支持SAT。替代证据不可显示成“现场已测”。

### 13.2 场景必须逐级执行

| 次序 | 场景 | 必须观察的内容 |
| --- | --- | --- |
| 11.1 | 单台储能拒绝充电或可用能力归零 | 从可调容量中剔除，其他储能受限分配，必要时光伏限功率 |
| 11.2 | 单台光伏或储能通信中断 | 超时识别、本地后备行为、实际功率证据及未知状态 |
| 11.3 | 零馈表失联或数据无效 | 退出依赖无效PCC反馈的闭环，执行批准降级并保持反馈失效告警 |
| 11.4 | 零馈表失联且光伏拒令 | 识别控制能力不足；储能仅按已验证能力配合；无法确认零馈时明确告警 |
| 11.5 | 仅零馈表先恢复或仅光伏先恢复 | 分别验证恢复，任一必要条件未满足均保持告警 |
| 11.6 | 恢复观察或闭环稳定期间再次失联/拒令 | 撤销恢复资格，重新降级，两个计时清零 |
| 11.7 | 两项恢复且持续稳定 | 完整通过重新观察与稳定窗口后，按授权解除告警 |

每个独立场景从已知基线开始并完成退出确认。复合场景中的连续事件属于同一个故障事件链，不在中途重建“正常”基线。场景顺序不得以简单下拉框随意跳过依赖。

### 13.3 失去 PCC 反馈时的判定边界

无有效PCC测量时，iEMS不得以最后值或模拟真值继续零馈闭环。降级可采用的光伏限制、储能策略和本地后备必须由型号及站点批准策略决定；不能假定“所有设备都降零”或“储能一定能够吸收”。

失联设备即使已配置本地后备，现场也不能仅凭通信消失确认其功率。若具备独立测量，可按批准方法验证；否则显示“实际输出未知”。储能协助应受SOC、BMS、温度、功率、能量余量及持续时间约束。

出现有效实测馈网越限时显示“已检测馈网越限”；失去测量或控制能力时显示“零馈无法保证”。两者可以并存，但不能相互冒充。必要的停机、隔离或保护动作由批准架构和现场规程确定，工作台不自行创造跳闸策略。

### 13.4 恢复状态机与防止告警反复解除

| 状态 | 进入或保持条件 | iEMS动作 |
| --- | --- | --- |
| 正常 | 有效反馈、控制能力和策略条件均成立 | 正常运行，连续监测 |
| 故障降级 | 任一必要条件失效 | 锁存故障事件；执行批准降级；计时归零 |
| 双项恢复观察 | 计量持续有效，受影响设备执行能力可验证 | 保持降级；累计资格观察时间Tq |
| 受限恢复闭环 | Tq满足且具备恢复授权 | 按批准斜率恢复；告警仍保持；累计稳定时间Ts |
| 恢复完成 | Ts满足且全部解除条件成立 | 解除运行告警，保留故障事件与证据 |

Tq与Ts是独立、连续的观察窗。窗口内缺测、数据陈旧、拒令、控制权丢失、必要设备能力不明或越界时，相应连续性立即失效；复发导致退回故障降级并清零两个窗口。不得沿用上一次累计时间，也不得只因通信重新连接就自动解除。

恢复资格不能依赖一个“在线”位。应证明新鲜计量、受影响设备的有效指令确认及实际响应、当前能力边界和必要联锁均满足。若缺少可安全验证的控制动作或足够反馈，则保持“恢复待验证”。告警确认仅表示人员已知悉，不等于故障解除。

稳定窗要求PCC有效实测处于批准目标带、设备实际响应满足判据且没有新的必要条件失效。反复复发次数达到批准升级条件时，保持人工介入状态并请求厂家协同；不能依靠无限自动重试消除告警。重启后保留未闭合事件，重新取得恢复资格。

### 13.5 无厂家依据时的确定行为

缺少Tq、Ts、超时、斜率、容差、后备动作或恢复权限依据时，列出具体缺项、型号/固件适用范围和责任方，状态为“待厂家确认”。可以在隔离模拟环境使用明确标注的演练值；现场相关自动控制或通过判定保持阻断。本文不规定统一的秒数、功率百分比或固定零馈购电偏置。

**输出。** 故障事件链、复发次数、计时重置点、两端设备和端口、告警触发与解除依据、控制动作、未知区间、曲线及厂家协同记录。

## 14 步骤12 恢复正常配置并连续观察

**执行顺序。** 结束故障注入和临时测试模式；撤销测试覆盖值；读回正常运行配置；确认控制权归属和正常策略；检查所有测试对象的退出状态；在批准负载、光照和SOC范围下进行连续运行观察。

观察时长和工况覆盖要求来自项目规程，不采用固定万能时长。记录运行限制、未覆盖工况、告警和可用能力。期间发生配置变化或相关异常时，停止累计，重新判定受影响测试及观察范围。

**放行。** 未残留测试注入、强制值、临时权限或未知设备状态；实际配置与交付基线一致；必要观察完成。若恢复失败，状态为“退出未完成”，不开放SAT签署。

**输出。** 最终配置快照、临时动作撤销清单、正常策略归属、连续观察记录和剩余限制。

## 15 步骤13 SAT 见证复核与签署

SAT是本项目约定范围内的现场验收测试，不等同于调试程序运行结束，也不替代法定检验或合同之外的验收。

**执行顺序。**

1. 将批准SAT条款逐项映射到本次设备范围、测试步骤、现场证据和批准判据。
2. 核查证据版本、设备SN、实际固件、时间质量、缺测和范围覆盖；识别模拟、硬件在环或替代证据。
3. 对必须现场见证或必须按SAT程序复测的项目生成执行批次；复测仍遵循03至12的依赖及退出要求，不从签署页面直接发出功率命令。
4. 逐项处置未测试、失败、证据不足、不适用及偏差。不能通过补一个人工勾选把结果改为通过。
5. 授权方根据合同权限作出签署决定，记录签署人身份、角色、时间、所签报告哈希及接受范围。

**结论分层。** 自动测试结论为“满足/不满足本条判据”；调试结论为“完成/未完成，附限制”；SAT结论为“通过/未通过/待完成”，仅在项目允许时支持“附条件接受”，并列明有权接受人、限制和关闭期限。厂家技术确认与业主/EPC验收签署分栏。

未解决的安全关键项、强制验收项或关键证据缺口不得被普通偏差豁免。审批权限和允许豁免范围必须在项目规程中明确；不以平台默认角色授予法律或合同权限。

**输出。** 签署版SAT报告、要求覆盖矩阵、原始记录索引、偏差和保留项。未签署报告明显标识其状态，不显示“项目已验收”。

## 16 步骤14 封存并移交 M3

**移交内容。** 最终M1配置、现场实际配置与设备清单、驱动和固件版本、测试包与判据版本、调试与SAT报告、原始曲线和日志、现场附件、签署、运行限制、备份恢复说明、保留问题及后续责任。

**执行要求。** M3按已签署范围接收交接包，核对文件完整性和哈希。完成交接不删除失败或复发历史。交付后的设备更换、固件升级、点表变化、控制策略或PCC映射变化形成新基线，并按依赖关系发起必要复测；旧证据保持只读且标明适用范围。

**完成状态。** “已移交M3”仅表示本次交接资料和范围已移交，不表示未来所有工况均安全或永久满足零馈要求。

## 附录B iEMS 测试程序与数据设计

### B.1 执行架构

工作台提交授权和测试请求；iEMS校验权限、配置摘要及前置证据；本地执行器调度驱动、采样和判定；事件日志向工作台及受控归档端同步。实时保护和本地设备保护不依赖浏览器或云连接。

每次动作具有唯一运行ID、步骤ID、设备ID、命令ID、有效期及授权范围。重复请求返回原动作状态；不能因网页重试重复下发。共享PCC的控制动作互斥；独立只读检测按驱动能力限流。

失联或重启时执行器先从持久化日志恢复状态，核对实际配置和设备状态，不能从中断点盲目续发功率指令。退出行为必须区分可通信设备的受控动作与失联设备的本地后备；动作无法验证时保留未知状态并要求处理。

### B.2 必需数据对象

| 对象 | 必需内容 |
| --- | --- |
| 会话 Session | 项目、控制器身份、环境、范围、M1哈希、参与角色、授权、时间质量 |
| 测试包 TestPackage | 版本、批准状态、型号/固件/驱动适用范围、步骤依赖、能力需求、退出规则 |
| 判据 Criterion | 指标、单位、阈值、时间窗、采样要求、适用工况、依据文档条款、批准方 |
| 执行记录 Run | 步骤、设备/端口/回路、前置结果、动作序列、开始结束、退出状态 |
| 观测 Observation | 原始值、换算值、单位、源/采集时间、质量、测量来源、序列号 |
| 证据 Evidence | 指令、确认、读回、曲线、日志、人工确认/照片、文件哈希与来源 |
| 异常 Issue | 故障事件ID、设备、原因证据、影响依赖、责任方、处理与复测关系 |
| SAT记录 Acceptance | 条款、覆盖证据、偏差、见证与签署身份、报告哈希、结论范围 |

执行状态采用“未开始、条件阻断、待授权、执行中、退出中、已结束、中止”；结果采用“通过、失败、证据不足、不适用”；判据依据另设“已批准、待厂家确认、已撤销”。环境是独立字段，不能仅靠颜色区分。

“不适用”需要模型条件及批准理由，不得作为跳过失败的通道。没有批准判据时可以保存诊断观测，但不能产生正式通过结果。厂家后续批准新判据不自动改写旧结果，必须保留原始评价并形成可追溯复核或复测。

### B.3 连续判定和证据有效性

时间窗内只有质量有效且时间连续的样本参与稳定判断；缺测、时间倒退或超过批准间隔使连续性中断。记录检测时刻和故障可确认起点的差异，禁止用未来样本回填当时未知的状态。

任何通过必须同时满足前置条件、动作完成、实测判据、环境标识和退出确认。结果汇总不得用平均数掩盖某台关键设备失败。保存模型与参数摘要，按变更依赖失效相关结果，而非静默删除历史或使全项目无差别重测。

## 附录C 厂家协同与依据闭环

示例工程范围为1台iEMS、10台125kW光伏并网机、10台125kW/261kWh储能、1套PCC零馈计量，以及所需配电、汇流、开关、网络和接地相关对象。合计光伏额定1.25MW，储能额定功率1.25MW、标称能量2.61MWh。具体型号、容量及SN以现场批准主数据为准。

单台iEMS统一控制20台功率设备是本示例的目标架构；设备数、通信口容量、驱动兼容及控制周期须以适用iEMS型号的批准能力证明核验，不能把设计意图写成已获厂家保证的能力。

## 附录E 产品实现验收要求

1. 前置测试未完成、过期或依据未批准时，不能调用依赖它的现场控制动作；服务端与iEMS端均执行校验。
2. 模拟结果不能进入现场通过数量、现场SAT结论或现场设备状态；硬件在环的混合来源完整标识。
3. 同型号合并显示后仍能定位每台SN、端口、原始结果和退出状态；组结果与逐台汇总一致。
4. 指令发送、应答、读回和实际功率响应四者分别记录；缺一个必要证据不能判通过。
5. PCC陈旧、冻结、异常、倍率或方向错误的场景能阻断控制；无效时间段不被补为正常值。
6. PV无光、BESS受SOC限制等工况不足能准确归类，不自动判设备失败或测试通过。
7. 浏览器刷新、重复点击、网络中断和iEMS重启不会重复执行物理动作；恢复后可查询原运行及退出状态。
8. 计量先恢复、PV先恢复、两者恢复及两种观察阶段的复发均按依赖验证；复发清零计时，未稳定不能解除。
9. 停止、退出失败、控制权丢失和未知实际状态均有明确界面，不用“完成”隐藏未恢复设备。
10. M1关键变更使受影响证据失效并生成复测范围，旧记录只读保留。
11. SAT要求覆盖矩阵能识别未测、失败、证据不足、不适用及未经授权偏差；只有有权人员能够签署对应范围。
12. 导出交接包能验证配置、证据、签署和哈希关联；离线本地记录可恢复同步且不覆盖已有证据。
