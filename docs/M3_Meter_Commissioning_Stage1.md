# M1 → M3：电表与 iEMS 分步验证第一阶段

- 独立 M2 导航取消，M1 L5 完成后直接进入 M3 调试与验证。建模必填门槛保留；未保存模型须先回 M1 保存。
- 五步：调试条件、接口与接线、通信参数、设备识别、数据有效性。接线总图嵌入接线步骤；端口与适用参数来自调试基线快照。
- 首次进入自动准备依据；模型变化后提示更新，旧结果不迁移为新依据的通过结果。
- 模拟和现场采用不同记录分区，均包含基线、通信回路、步骤、前置结果 ID、来源、时间与版本。服务端强制检查前置关系，不能只靠前端按钮限制。
- 模拟使用明确标注的合成场景，正常或故障均由服务端生成；不读取真实设备，不改 M1 参数，不推定实际接口兼容。
- 现场仅保存人工观察与文档 / 照片引用。EPC 可记录现场前提确认；后续功能未接入受控厂家判据，因此不允许选通过，保持待确认或异常。没有将人工填写引用当作系统批准。
- 重做前置步骤会使其后的旧结果失效，必须重新验证；异常阻止依赖步骤执行，可预览后续指引。
- 旧 M2 点检、照片和工作包只读保留，不作为 M3 通过依据。

当前范围只验证电表与 iEMS 的直接通信链路。尚未实现真实设备连接、受控厂家判据批准、零馈动态联调、多操作人权限与现场审批。本次不是系统投运或验收结论。

验证：39 项后端回归；M3 浏览器流程覆盖五步正常模拟、故障阻断、模式隔离、前置结果失效、刷新持久化、M1 入口与只读历史。
