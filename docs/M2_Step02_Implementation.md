# 步骤02 iEMS 自检实现计划

依据用户批准的步骤02设计，执行以下增量，不启动任何真实硬件动作。

- [x] backend/iems_selfcheck.py：生成按顺序的模拟观测、判据、原因、处理、责任方与依据缺项；只读能力和功率控制权限分列。
- [x] backend/meter_workflow.py、store.py：持久化初始快照、接口清单及范围约束；按请求ID去重，提供原运行查询；失败使下游失效。
- [x] frontend/src/IemsSelfcheck.tsx：自动结果列表、异常优先、厂家待确认、模拟场景、恢复查询；接入 MeterWorkflow。
- [x] tests/test_iems_selfcheck.py：异常阻断、只读放行、现场隔离、并发去重与恢复查询。页面测试覆盖异常恢复和刷新。
- [x] 构建、回归及实际浏览器查看，输出实际截图。

边界：当前会话仅包含零馈计量范围。即使模拟自检满足判据，功率动作仍锁定；真实控制租约、退出策略和通信引导写入未接入。模拟租约仅表示本轮只读测试的范围与执行所有者，不授予现场权限。未知设备只展示候选，不写回 M1。


验证记录：完整后端回归72项通过；遇错停止调整后，步骤02两项专项测试再次通过。顺序零馈流程与自检页面两项浏览器测试通过，前端生产构建通过。实际 CI-20 页面演示所有权丢失、后续未执行、无远程写权限只读可用和原运行查询。

运行接口沿用 meter-workflow/{session_id}/run，新增 request_id；同一会话及请求ID以数据库唯一键保留一份不可变记录，重复请求不得更改动作。GET meter-workflow/{session_id}/runs/{request_id} 查询原记录，查询不启动动作。浏览器保留待查询请求ID，结果未确认时禁用新运行。

当前去重仅覆盖纯模拟计算和证据记录。接入真实硬件之前必须实现控制器侧持久化命令日志、执行状态机、租约到期与撤销及批准退出动作；不能把模拟记录去重当作物理动作的一次执行保证。当前没有现场配置写入、控制租约或退出命令，现场测试保持不可用。
